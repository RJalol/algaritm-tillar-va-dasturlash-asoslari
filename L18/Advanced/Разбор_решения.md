# Разбор решения. L18-ALG-021. Пять нарушений в одном фрагменте

## Условие
Дан код:

```
class Demo
{
    public string Code { get; }
    public int Computed => 42;
    public Demo(string code) { Code = code; }

    public int F(int a)    { return a; }
    public double F(int a) { return a; }
}

class Amb
{
    public static void G(int a, double b) { }
    public static void G(double a, int b) { }
}

Demo d = new Demo("X");
d.Code = "Y";
d.Computed = 1;
Amb.G(1, 2);
```

Найти все нарушения, назвать код ошибки для каждого и разнести их по трём группам: невозможность различить перегрузки; невозможность выбрать перегрузку; присваивание тому, что присваивать нельзя. Привести исправленный фрагмент.

## Ожидаемый результат
Названы коды `CS0111`, `CS0121` и `CS0200` (дважды); группы разнесены верно; отмечено, что два случая `CS0200` различаются устройством свойства, но не кодом ошибки.

## Разбор условия
**Дано:** класс `Demo` с перегрузками и свойствами, класс `Amb` с неоднозначными перегрузками и три присваивания.
**Требуется:** найти нарушения, назвать коды (`CS0111`, `CS0121`, `CS0200` ×2), разнести по трём группам.

## Теоретическая справка
- **Неразличимые перегрузки.** Методы `int F(int)` и `double F(int)` отличаются только типом результата, поэтому их сигнатуры совпадают (`CS0111`).
- **Неоднозначный выбор.** Вызов `G(1, 2)` подходит под `G(int, double)` и `G(double, int)`: каждая перегрузка требует одного неявного преобразования, лучшей нет (`CS0121`). Устранение: явное приведение `G(1, 2.0)` либо иная перегрузка.
- **Запись в свойство без `set`.** Автосвойство `{ get; }` присваивается только в конструкторе; свойство-выражение `=> 42` вычисляется и вовсе не имеет сеттера. В обоих случаях присваивание вне конструктора — `CS0200`.

## Идея решения
Анализируем перегрузки (отличаются ли списки параметров, однозначен ли выбор) и присваивания свойствам без `set`.

## Решение
```csharp
// Исправленный фрагмент
class Demo
{
    public string Code { get; set; }               // добавлен set
    public int Computed => 42;
    public Demo(string code) { Code = code; }
    public int F(int a)       { return a; }
    public double F(double a) { return a; }       // другой список параметров
}
class Amb
{
    public static void G(int a, double b) { }
    public static void G(double a, int b) { }
}
Demo d = new Demo("X");
d.Code = "Y";
Amb.G(1, 2.0);                                   // однозначный выбор
```

## Пошаговое объяснение
1. Невозможность различить: `int F(int)` и `double F(int)` отличаются лишь типом результата (`CS0111`).
2. Невозможность выбрать: `Amb.G(1, 2)` подходит под обе перегрузки с одинаковой «стоимостью» преобразований (`CS0121`).
3. Присваивание недоступному: `d.Code = "Y"` — свойство `Code` без `set` (`CS0200`) и `d.Computed = 1` — вычисляемое свойство только для чтения (`CS0200`). Устройство различается (автосвойство без сеттера и свойство-выражение), код ошибки одинаков.

## Трассировка и проверка
| Фрагмент | Группа | Код |
|---|---|---|
| `int F(int)` и `double F(int)` | неразличимые перегрузки | CS0111 |
| `Amb.G(1, 2)` | неоднозначный выбор | CS0121 |
| `d.Code = "Y"` | свойство только для чтения | CS0200 |
| `d.Computed = 1` | вычисляемое свойство | CS0200 |

Коды совпадают, а причины различаются: для `Code` достаточно добавить `set`/`init`, для `Computed` присваивание не имеет смысла.

## Результат
Коды: CS0111, CS0121, CS0200 (дважды).

## Типичные ошибки
- Проектировать перегрузки, различающиеся только порядком неявных преобразований.
- Присваивать автосвойству только для чтения вне конструктора.
- Не замечать, что вычисляемое свойство нельзя присвоить.
- Игнорировать `init` (C# 9) как способ задать значение при инициализации объекта.
