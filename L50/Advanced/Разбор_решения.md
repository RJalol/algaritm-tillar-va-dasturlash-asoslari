# Разбор решения. L50 · Задание III · №1. Паттерн MVVM

## Условие
Реализовать простейшее приложение по MVVM: модель, модель представления с командами, разметка без кода в `.xaml.cs`.

## Ожидаемый результат
Логика не зависит от окна.

## Разбор условия
**Дано:** счётчик.
**Требуется:** реализовать приложение по MVVM: ViewModel с командами, XAML без кода в окне.

## Теоретическая справка
**MVVM (Model–View–ViewModel):**

| Слой | Ответственность |
|---|---|
| Model | данные и бизнес-логика |
| ViewModel | состояние представления и команды; не знает об элементах интерфейса |
| View (XAML) | разметка; привязана к ViewModel |

Механизмы связи:

- `INotifyPropertyChanged` — ViewModel уведомляет представление об изменениях;
- `ICommand` — команды вместо обработчиков `Click`; `CanExecute` включает/отключает кнопку автоматически;
- `DataContext` — объект, на свойства которого ссылаются привязки.

Преимущества: логику можно тестировать без окна, интерфейс — менять без правки логики.

## Идея решения
MVVM разделяет приложение на модель данных, модель представления (ViewModel, содержит состояние и команды) и представление (XAML). Представление привязывается к ViewModel и не содержит логики.

## Решение
```csharp
// ---- RelayCommand.cs ----
using System;
using System.Windows.Input;

public class RelayCommand : ICommand
{
    private readonly Action<object> _execute;
    private readonly Predicate<object> _canExecute;

    public RelayCommand(Action<object> execute, Predicate<object> canExecute = null)
    { _execute = execute; _canExecute = canExecute; }

    public bool CanExecute(object parameter) => _canExecute?.Invoke(parameter) ?? true;
    public void Execute(object parameter) => _execute(parameter);
    public event EventHandler CanExecuteChanged
    {
        add => CommandManager.RequerySuggested += value;
        remove => CommandManager.RequerySuggested -= value;
    }
}

// ---- MainViewModel.cs ----
using System.ComponentModel;
using System.Runtime.CompilerServices;

public class MainViewModel : INotifyPropertyChanged
{
    private int _count;
    public int Count
    {
        get => _count;
        set { _count = value; OnPropertyChanged(); }
    }

    public RelayCommand Increment { get; }
    public RelayCommand Reset { get; }

    public MainViewModel()
    {
        Increment = new RelayCommand(_ => Count++);
        Reset = new RelayCommand(_ => Count = 0, _ => Count != 0);
    }

    public event PropertyChangedEventHandler PropertyChanged;
    private void OnPropertyChanged([CallerMemberName] string name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}

// ---- MainWindow.xaml ----
// <Window ... xmlns:local="clr-namespace:MvvmDemo" Title="MVVM" Width="300" Height="160">
//   <Window.DataContext><local:MainViewModel/></Window.DataContext>
//   <StackPanel Margin="15">
//     <TextBlock Text="{Binding Count}" FontSize="28"/>
//     <Button Content="+1"    Command="{Binding Increment}" Margin="0,8,0,0"/>
//     <Button Content="Сброс" Command="{Binding Reset}"     Margin="0,8,0,0"/>
//   </StackPanel>
// </Window>
```

## Пошаговое объяснение
1. ViewModel реализует `INotifyPropertyChanged`: при изменении `Count` вызывается `OnPropertyChanged`, и привязанные элементы обновляются.
2. Команды `ICommand` заменяют обработчики `Click`: кнопка выполняет `Execute`, а доступность определяет `CanExecute` — кнопка «Сброс» неактивна, пока `Count == 0`.
3. `RelayCommand` — небольшой вспомогательный класс, принимающий делегаты и тем самым избавляющий от отдельного класса на каждую команду.
4. В XAML окну назначается `DataContext` — экземпляр ViewModel; привязки `{Binding Count}`, `{Binding Increment}` ищут свойства именно в нём.
5. В `MainWindow.xaml.cs` кода нет, поэтому логику можно тестировать без окна.

## Трассировка и проверка
| Действие | `Count` | Кнопка «Сброс» |
|---|--:|---|
| старт | 0 | отключена (`CanExecute` = false) |
| «+1» ×3 | 3 | включена |
| «Сброс» | 0 | отключена |

Все изменения отображаются без единой строки кода в `MainWindow.xaml.cs`.

## Результат
Счётчик увеличивается кнопкой «+1», обнуляется кнопкой «Сброс» (недоступной при нуле); код окна не содержит логики.

## Типичные ошибки
- Забыть вызвать `OnPropertyChanged` — интерфейс не обновляется.
- Обращаться из ViewModel к элементам интерфейса (нарушение MVVM).
- Не задать `DataContext`.
- Не обновлять `CanExecute` (используют `CommandManager.RequerySuggested`).
