# Разбор решения. L25 · Задание III · №1. Иерархия учебного заведения

## Условие
Разработать иерархию из шести классов: «человек» — «студент», «преподаватель», «сотрудник»; «студент» — «выпускник»; «преподаватель» — «заведующий кафедрой». Общие члены объявить в базовом классе, доступ разграничить модификаторами `private`, `protected` и `public` осмысленно. Классы разместить по файлам согласно теме №21. Программа заполняет массив базового типа не менее чем десятью объектами и печатает отчёт с указанием фактического класса каждого.

## Ожидаемый результат
Отчёт выведен; ни один член не продублирован в производных классах; для каждого поля обоснован выбор модификатора доступа.

## Разбор условия
**Дано:** учебное заведение.
**Требуется:** иерархия из шести классов, общие члены в базовом, осмысленный выбор `private`/`protected`/`public`, массив базового типа из десяти объектов, отчёт с фактическим классом.

## Теоретическая справка
**Проектирование иерархии.** Общие данные и поведение выносятся в корень (`Person`); специализации добавляют только своё. Признак ошибки — дублирование членов в наследниках.

**Выбор доступа:**

| Член | Модификатор | Обоснование |
|---|---|---|
| год рождения | `private` | внутреннее состояние `Person`; наружу — только возраст |
| имя | `protected` (свойство) | нужно наследникам для формирования описания |
| кафедра | `protected` | нужна наследникам преподавателя |
| конструкторы, `Age`, `Role` | `public` | интерфейс для клиентов |

**Переопределение (`virtual`/`override`)** `Role` позволяет получать роль без проверок типа.

## Идея решения
Общие члены (имя, год рождения) живут в базовом классе `Person`. Поля делаем `protected`/`private` по назначению: что нужно наследникам — `protected`, служебное — `private`, интерфейс для внешнего мира — `public`. Для краткости показаны все классы в одном листинге (в проекте — по файлам, согласно теме №21).

## Решение
```csharp
using System;

namespace University
{
    public class Person
    {
        private readonly int _birthYear;            // нужен только Person: private
        protected string Name { get; }              // нужен наследникам: protected
        public Person(string name, int birthYear) { Name = name; _birthYear = birthYear; }
        public int Age(int year) => year - _birthYear;
        public virtual string Role => "человек";
        public override string ToString() => $"{Role}: {Name}";
    }

    public class Student : Person
    {
        protected int Course { get; }
        public Student(string n, int by, int course) : base(n, by) { Course = course; }
        public override string Role => $"студент {Course} курса";
    }

    public class Graduate : Student
    {
        public Graduate(string n, int by) : base(n, by, 4) { }
        public override string Role => "выпускник";
    }

    public class Teacher : Person
    {
        protected string Department { get; }
        public Teacher(string n, int by, string dep) : base(n, by) { Department = dep; }
        public override string Role => $"преподаватель кафедры {Department}";
    }

    public class DepartmentHead : Teacher
    {
        public DepartmentHead(string n, int by, string dep) : base(n, by, dep) { }
        public override string Role => $"заведующий кафедрой {Department}";
    }

    public class Staff : Person
    {
        public Staff(string n, int by) : base(n, by) { }
        public override string Role => "сотрудник";
    }

    class Program
    {
        static void Main()
        {
            Person[] people =
            {
                new Student("Азиз", 2006, 2), new Student("Малика", 2005, 3),
                new Graduate("Рустам", 2002), new Graduate("Лола", 2003),
                new Teacher("Нодира", 1985, "Информатика"), new Teacher("Бобур", 1980, "Математика"),
                new DepartmentHead("Саид", 1970, "Информатика"),
                new Staff("Камола", 1990), new Staff("Тимур", 1995),
                new Person("Гость", 2000)
            };

            foreach (Person p in people)
                Console.WriteLine($"{p.GetType().Name,-15} {p}, возраст {p.Age(2026)}");
        }
    }
}
```

## Пошаговое объяснение
1. Иерархия: Person → Student → Graduate; Person → Teacher → DepartmentHead; Person → Staff. Всего шесть производных классов и базовый.
2. Выбор модификаторов: `_birthYear` — `private` (внутреннее состояние Person, снаружи доступен только возраст через метод); `Name`, `Course`, `Department` — `protected` (нужны наследникам для формирования роли); конструкторы, `Age`, `Role` — `public`.
3. Ни одно поле не дублируется: производные классы лишь добавляют специфические члены.
4. Метод `Role` переопределяется в каждом наследнике, поэтому при вызове через ссылку `Person` в отчёте печатается соответствующая роль, а `GetType().Name` показывает фактический класс.
5. Массив из десяти объектов обходится одним циклом `foreach`.

## Трассировка и проверка
Фрагмент отчёта:

| Фактический класс | Роль | Возраст |
|---|---|--:|
| Student | студент 2 курса | 20 |
| Graduate | выпускник | 24 |
| Teacher | преподаватель кафедры Информатика | 41 |
| DepartmentHead | заведующий кафедрой Информатика | 56 |
| Staff | сотрудник | 36 |

Каждый объект хранится в `Person[]`; цикл `foreach` обходит все десять объектов одинаково.

## Результат
Десять строк отчёта с фактическим классом, ролью и возрастом каждого человека.

## Типичные ошибки
- Открывать все поля `public`.
- Дублировать `Name` в каждом наследнике.
- Строить глубокую иерархию без необходимости (3–4 уровня обычно достаточно).
- Проверять тип через `is` в цикле вместо виртуального метода.
