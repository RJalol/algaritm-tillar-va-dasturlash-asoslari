# Разбор решения. L33 · Задание II · №1. Иерархия фигур на абстрактном классе

## Условие
Переписать иерархию фигур темы №32 так, чтобы базовый класс стал абстрактным, а методы вычисления площади и периметра — абстрактными. Сохранить в базовом классе реализованный метод описания, обращающийся к абстрактным членам. Вычислить суммы по массиву из шести фигур и сравнить решение с исходным по числу строк и по надёжности.

## Ожидаемый результат
Результаты совпадают с решением темы №32; в базовом классе не осталось ни одной бессмысленной реализации; объект базового класса создать нельзя.

## Идея решения
Базовая `Shape` становится абстрактной: площадь и периметр объявляются `abstract`, поэтому «пустые» реализации (0) в базовом классе не нужны. Метод описания остаётся реализованным и пользуется абстрактными членами.

## Решение
```csharp
using System;

abstract class Shape
{
    public abstract string Name { get; }
    public abstract double Area();
    public abstract double Perimeter();

    public string Describe() => $"{Name}: S = {Area():F2}, P = {Perimeter():F2}";
}

class Rectangle : Shape
{
    public double A { get; }
    public double B { get; }
    public Rectangle(double a, double b) { A = a; B = b; }
    public override string Name => "Прямоугольник";
    public override double Area() => A * B;
    public override double Perimeter() => 2 * (A + B);
}

class Square : Rectangle
{
    public Square(double a) : base(a, a) { }
    public override string Name => "Квадрат";
}

class Circle : Shape
{
    public double R { get; }
    public Circle(double r) { R = r; }
    public override string Name => "Круг";
    public override double Area() => Math.PI * R * R;
    public override double Perimeter() => 2 * Math.PI * R;
}

class Triangle : Shape
{
    public double A { get; }
    public double B { get; }
    public double C { get; }
    public Triangle(double a, double b, double c) { A = a; B = b; C = c; }
    public override string Name => "Треугольник";
    public override double Perimeter() => A + B + C;
    public override double Area()
    {
        double p = Perimeter() / 2;
        return Math.Sqrt(p * (p - A) * (p - B) * (p - C));
    }
}

class Program
{
    static void Main()
    {
        Shape[] shapes =
        {
            new Rectangle(3, 4), new Circle(1), new Triangle(3, 4, 5),
            new Square(2), new Rectangle(1, 5), new Circle(2)
        };

        double area = 0, perimeter = 0;
        foreach (Shape s in shapes)
        {
            Console.WriteLine(s.Describe());
            area += s.Area(); perimeter += s.Perimeter();
        }
        Console.WriteLine($"Сумма площадей: {area:F2}, сумма периметров: {perimeter:F2}");
    }
}
```

## Пошаговое объяснение
1. Единственное изменение иерархии по сравнению с темой №32: `Shape` стал `abstract`, `Area`, `Perimeter`, `Name` — `abstract`; базовые заглушки удалены (на 6 строк короче).
2. Надёжность выросла: нельзя создать «фигуру вообще» с нулевой площадью, а забыть реализовать метод в новом наследнике — ошибка компиляции (`CS0534`), а не молчаливый ноль.
3. `Describe()` реализован один раз в базовом классе и работает для всех фигур, обращаясь к абстрактным членам.
4. Результаты совпадают с решением темы №32 (≈ 42,71 и ≈ 64,85).

## Результат
Суммы совпадают с решением темы №32; объект класса Shape создать нельзя (CS0144), у наследника без реализации — CS0534.
