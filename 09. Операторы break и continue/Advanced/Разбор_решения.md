# Разбор решения. L09-ALG-021. Три нарушения в одном фрагменте

## Условие
Дан код:

```
int x = 5;
if (x > 0)
{
    break;
}

for (int i = 1; i <= 3; i++)
{
    goto Finish;
}

for (int i = 1; i <= 5; i++)
{
    break;
    Console.WriteLine(i);
}
```

Найти все нарушения, для каждого назвать код сообщения компилятора и объяснить причину отдельно. Указать, какие два из них являются ошибками, а какое — предупреждением, и почему различие существенно. Привести исправленный фрагмент.

## Ожидаемый результат
Три сообщения: ошибки `CS0139` и `CS0159`, предупреждение `CS0162`; отмечено, что предупреждение не препятствует сборке, из-за чего соответствующая ошибка проявляется только в поведении программы.

## Разбор условия
**Дано:** три фрагмента с `break`, `goto`, недостижимым кодом.
**Требуется:** найти сообщения (`CS0139`, `CS0159`, `CS0162`), отметить, что два из них — ошибки, одно — предупреждение, исправить.

## Теоретическая справка
**Ошибка компиляции** прерывает сборку; **предупреждение** — нет, программа запускается. Поэтому ошибка не может «просочиться» в работающую программу, а предупреждение может.

- `break` допустим только внутри цикла или `switch` (`CS0139` иначе).
- `goto метка;` требует объявленной метки в доступной области (`CS0159` — метка не найдена).
- Код после безусловного `break`, `return`, `throw`, `goto` недостижим; компилятор сообщает об этом предупреждением `CS0162` — но не мешает сборке.

## Идея решения
Выясняем, где `break` и `goto` недопустимы, и какие сообщения останавливают сборку, а какие — нет.

## Решение
```csharp
// Исправленный фрагмент
int x = 5;
if (x > 0)
{
    Console.WriteLine("положительное");   // break вне цикла недопустим
}

for (int i = 1; i <= 3; i++)
{
    goto Finish;
}
Finish:
Console.WriteLine("конец");

for (int i = 1; i <= 5; i++)
{
    Console.WriteLine(i);
    break;
}
```

## Пошаговое объяснение
1. `break` внутри `if`, не находящегося в цикле или `switch`, — ошибка `CS0139`: прерывать нечего.
2. `goto Finish;` без объявленной метки `Finish` — ошибка `CS0159`: метка не найдена (после её добавления переход выходит из цикла).
3. `Console.WriteLine(i);` после `break` — недостижимый код; это лишь предупреждение `CS0162`, сборка не прерывается.
4. Различие существенно: ошибки не дают получить программу, а предупреждение допускает её запуск, поэтому недостижимая строка тихо не выполняется и проявляется только в поведении программы.

## Трассировка и проверка
| Сообщение | Вид | Влияние на сборку |
|---|---|---|
| CS0139 | ошибка | сборка невозможна |
| CS0159 | ошибка | сборка невозможна |
| CS0162 | предупреждение | сборка проходит, строка просто не выполняется |

Именно предупреждения легко пропустить: цикл `for` с `break` в начале тела выполняет ровно одну итерацию, а оператор вывода после него никогда не вызовется — программа работает, но не делает нужного. Режим «обрабатывать предупреждения как ошибки» (`TreatWarningsAsErrors`) защищает от этого.

## Результат
Две ошибки (CS0139, CS0159) и предупреждение CS0162; исправлено расположением break, добавлением метки и перестановкой вывода перед break.

## Типичные ошибки
- Игнорировать предупреждения компилятора.
- Использовать `goto` для выхода из нескольких вложенных циклов без нужды.
- Помещать `break` до полезных операторов и «терять» их.
- Считать, что метка видна из любой части метода — область видимости метки ограничена.

## Задания для закрепления

- Переписать выход из двух вложенных циклов без `goto` (через флаг или метод).
- Найти в своём коде все предупреждения и классифицировать их.
