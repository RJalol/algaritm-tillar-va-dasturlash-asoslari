# Разбор решения. L32 · Задание II · №1. Иерархия фигур

## Условие
Построить иерархию «фигура» — «прямоугольник», «круг», «треугольник», «квадрат», объявив в базовом классе виртуальные методы вычисления площади и периметра и виртуальный метод названия. Каждый производный класс переопределяет то, что для него отличается, и **не** переопределяет то, что подходит без изменений. Вычислить суммарные площадь и периметр массива из шести фигур.

## Ожидаемый результат
Суммы вычислены верно; не менее чем в одном классе оставлена унаследованная реализация без переопределения, что отмечено в комментарии.

## Разбор условия
**Дано:** иерархия фигур.
**Требуется:** виртуальные площадь, периметр, название; переопределять только отличающееся; суммировать по массиву из шести фигур.

## Теоретическая справка
**Принцип подстановки Лисков:** объект производного класса можно использовать везде, где ожидается базовый, без нарушения правильности. Поэтому виртуальный метод в наследнике должен сохранять смысл базового.

**Минимизация переопределений.** Квадрат — частный случай прямоугольника: его площадь и периметр вычисляются теми же формулами, поэтому достаточно унаследовать их и переопределить лишь название. Лишние переопределения увеличивают объём кода и риск расхождений.

Недостаток иерархии «квадрат — прямоугольник» (изменяемые стороны) рассматривается как классический пример нарушения принципа Лисков.

## Идея решения
В базовом классе — виртуальные `Area`, `Perimeter`, `Name`. Каждый наследник переопределяет только то, что отличается. Квадрат — частный случай прямоугольника: он наследует `Area` и `Perimeter` прямоугольника без переопределения и меняет только `Name`.

## Решение
```csharp
using System;

class Shape
{
    public virtual string Name => "Фигура";
    public virtual double Area() => 0;
    public virtual double Perimeter() => 0;
}

class Rectangle : Shape
{
    public double A { get; }
    public double B { get; }
    public Rectangle(double a, double b) { A = a; B = b; }

    public override string Name => "Прямоугольник";
    public override double Area() => A * B;
    public override double Perimeter() => 2 * (A + B);
}

class Square : Rectangle
{
    public Square(double a) : base(a, a) { }

    public override string Name => "Квадрат";
    // Area() и Perimeter() унаследованы от Rectangle без переопределения: формулы подходят.
}

class Circle : Shape
{
    public double R { get; }
    public Circle(double r) { R = r; }

    public override string Name => "Круг";
    public override double Area() => Math.PI * R * R;
    public override double Perimeter() => 2 * Math.PI * R;
}

class Triangle : Shape
{
    public double A { get; }
    public double B { get; }
    public double C { get; }
    public Triangle(double a, double b, double c) { A = a; B = b; C = c; }

    public override string Name => "Треугольник";
    public override double Perimeter() => A + B + C;
    public override double Area()
    {
        double p = Perimeter() / 2;                       // формула Герона
        return Math.Sqrt(p * (p - A) * (p - B) * (p - C));
    }
}

class Program
{
    static void Main()
    {
        Shape[] shapes =
        {
            new Rectangle(3, 4), new Circle(1), new Triangle(3, 4, 5),
            new Square(2), new Rectangle(1, 5), new Circle(2)
        };

        double area = 0, perimeter = 0;
        foreach (Shape s in shapes)
        {
            Console.WriteLine($"{s.Name}: S = {s.Area():F2}, P = {s.Perimeter():F2}");
            area += s.Area();
            perimeter += s.Perimeter();
        }
        Console.WriteLine($"Сумма площадей: {area:F2}");
        Console.WriteLine($"Сумма периметров: {perimeter:F2}");
    }
}
```

## Пошаговое объяснение
1. Базовые виртуальные члены возвращают нейтральные значения (0 и «Фигура»), чтобы класс можно было создавать.
2. `Rectangle` переопределяет все три члена; `Square` наследует `Rectangle` и меняет лишь `Name` — переопределение `Area`/`Perimeter` не нужно, формулы верны (отмечено комментарием).
3. `Triangle` вычисляет площадь по формуле Герона, использовав уже переопределённый `Perimeter()`.
4. В цикле по `Shape[]` все вызовы разрешаются по фактическому типу, поэтому суммы считаются без проверок типа.
5. Проверка: 12 + 3,14 + 6 + 4 + 5 + 12,57 ≈ 42,71; периметры 14 + 6,28 + 12 + 8 + 12 + 12,57 ≈ 64,85.

## Трассировка и проверка
Фигуры: Rectangle(3,4), Circle(1), Triangle(3,4,5), Square(2), Rectangle(1,5), Circle(2).

| Фигура | S | P |
|---|--:|--:|
| Rectangle(3,4) | 12,00 | 14,00 |
| Circle(1) | 3,14 | 6,28 |
| Triangle(3,4,5) | 6,00 | 12,00 |
| Square(2) | 4,00 | 8,00 |
| Rectangle(1,5) | 5,00 | 12,00 |
| Circle(2) | 12,57 | 12,57 |
| **Сумма** | **42,71** | **64,85** |

## Результат
Сумма площадей ≈ 42,71; сумма периметров ≈ 64,85.

## Типичные ошибки
- Переопределять унаследованные формулы без необходимости.
- Возвращать из базового класса бессмысленные значения (0) вместо абстрактных членов (см. тему №33).
- Делать поля изменяемыми у `Square`/`Rectangle`.
- Проверять тип фигуры в цикле вместо вызова виртуального метода.
