# Разбор решения. L01-ALG-021. Подсчёт количества простых чисел в диапазоне

## Условие
Даны границы диапазона A и B (1 ≤ A ≤ B). Составить алгоритм подсчёта количества простых чисел в этом диапазоне включительно (числа 0 и 1 простыми не являются).

## Ожидаемый результат
Верное количество простых чисел в диапазоне (например, при A = 2, B = 10 — count = 4).

## Разбор условия
**Дано:** границы диапазона `A` и `B`, 1 ≤ A ≤ B.
**Требуется:** посчитать, сколько простых чисел содержит отрезок [A; B] (границы включаются).
**Уточнения:** 0 и 1 простыми не считаются; простое число — натуральное, больше 1, делящееся только на 1 и на себя.

## Теоретическая справка
**Циклический алгоритм** повторяет группу действий. Здесь используются два вложенных цикла:

1. внешний (`для n от A до B`) — перебор кандидатов;
2. внутренний (`пока d * d <= n и prime`) — перебор возможных делителей.

**Почему достаточно проверять делители до √n.** Если `n = p · q` и `p ≤ q`, то `p² ≤ p · q = n`, то есть меньший делитель не превосходит √n. Значит, если делителя до √n нет, то нет и вообще. Условие `d * d <= n` позволяет обойтись без вычисления корня.

**Признак (флаг) `prime`** — логическая переменная, запоминающая итог проверки. Она позволяет выйти из внутреннего цикла сразу после находки делителя.

## Идея решения
Для каждого числа n из диапазона проверяем простоту: n > 1 и нет делителей d с 2 ≤ d и d·d ≤ n. Подсчитываем число успешных проверок. Условие d·d ≤ n достаточно, потому что у составного числа обязательно есть делитель, не превышающий √n.

## Решение
```text
Алгоритм «Количество простых в [A; B]»
начало
  ввод A, B
  count := 0
  для n от A до B выполнять
    если n >= 2 то
      prime := истина
      d := 2
      пока d * d <= n и prime выполнять
        если n mod d = 0 то prime := ложь
        d := d + 1
      если prime то count := count + 1
  вывод count
конец
```

## Пошаговое объяснение
1. Обнуляем счётчик `count` и перебираем все числа `n` от `A` до `B` включительно.
2. Числа 0 и 1 простыми не считаются, поэтому проверку начинаем с `n >= 2`.
3. Предполагаем, что `n` простое (`prime := истина`), и перебираем делители от 2, пока `d·d <= n`.
4. Если найден делитель (`n mod d = 0`), число составное — сбрасываем признак `prime`; цикл при этом заканчивается досрочно по условию `и prime`.
5. Если после цикла признак остался истинным, увеличиваем `count`.
6. Трассировка для A = 2, B = 10: простыми окажутся 2, 3, 5, 7 → `count = 4`.

## Трассировка и проверка
Трассировка для A = 2, B = 10:

| n | делители d (пока d·d ≤ n) | prime | count |
|---:|---|:--:|---:|
| 2 | d=2: 4 > 2, цикл не выполняется | да | 1 |
| 3 | d=2: 4 > 3, цикл не выполняется | да | 2 |
| 4 | d=2: 4 mod 2 = 0 → найден делитель | нет | 2 |
| 5 | d=2: 4 ≤ 5, 5 mod 2 ≠ 0; d=3: 9 > 5 | да | 3 |
| 6 | d=2: 6 mod 2 = 0 | нет | 3 |
| 7 | d=2, d=3 (9 > 7) — делителей нет | да | 4 |
| 8, 9, 10 | делятся на 2 или 3 | нет | 4 |

Ответ: 4 (числа 2, 3, 5, 7). Дополнительные проверки: A = B = 1 → 0; A = B = 2 → 1; A = 1, B = 100 → 25.

## Результат
При A = 2, B = 10 результат count = 4; при A = B = 1 результат 0.

## Типичные ошибки
- Считать простыми 0 и 1 (проверка `n >= 2` обязательна).
- Начинать перебор делителей с 1 — тогда любое число окажется «составным», так как делится на 1.
- Проверять делители до `n - 1` — алгоритм верен, но намного медленнее; до √n достаточно.
- Не сбрасывать признак `prime := истина` для каждого нового `n` — результат предыдущей проверки «протекает» в следующую.
