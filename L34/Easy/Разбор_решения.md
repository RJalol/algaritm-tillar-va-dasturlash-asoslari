# Разбор решения. L34 · Задание I · №1. Первый интерфейс

## Условие
Объявить интерфейс «вывод сведений» с одним методом и одним свойством только для чтения. Реализовать его двумя не связанными наследованием классами. Написать метод, принимающий параметр типа интерфейса, и вызвать его для объектов обоих классов через массив типа интерфейса.

## Ожидаемый результат
Метод отработал для обоих классов, ничего о них не зная; массив типа интерфейса содержит объекты обоих классов; попытка создать объект интерфейса даёт `CS0144`.

## Разбор условия
**Дано:** два не связанных класса «книга» и «автомобиль».
**Требуется:** интерфейс с методом и свойством только для чтения; метод, принимающий параметр типа интерфейса; массив интерфейса из обоих объектов; ошибка при создании объекта интерфейса.

## Теоретическая справка
**Интерфейс** — набор членов (методов, свойств, событий) без реализации; описывает, **что** умеет тип, а не **как**. Класс заявляет `: IИнтерфейс` и обязан реализовать все его члены.

Отличия от абстрактного класса:

- классов можно наследовать только один, интерфейсов реализовать — сколько угодно;
- интерфейс не содержит состояния (полей) и конструкторов;
- интерфейс связывает *не родственные* типы общей способностью (`IComparable`, `IDisposable`).

Имена интерфейсов по соглашению начинаются с `I`.

## Идея решения
Интерфейс описывает «договор» (набор членов без реализации). Его могут реализовать любые классы, независимо от наследования. Метод, принимающий параметр типа интерфейса, работает со всеми такими классами.

## Решение
```csharp
using System;

interface IPrintable
{
    string Title { get; }
    void Print();
}

class Book : IPrintable
{
    public string Title { get; }
    public Book(string title) { Title = title; }
    public void Print() => Console.WriteLine("Книга: " + Title);
}

class Car : IPrintable
{
    private readonly string _model;
    public Car(string model) { _model = model; }
    public string Title => _model;
    public void Print() => Console.WriteLine("Автомобиль: " + _model);
}

class Program
{
    static void Show(IPrintable item)
    {
        Console.WriteLine($"[{item.Title}]");
        item.Print();
    }

    static void Main()
    {
        IPrintable[] items = { new Book("Алгоритмы"), new Car("Nexia") };
        foreach (IPrintable i in items) Show(i);

        // IPrintable p = new IPrintable();   // CS0144: интерфейс не может иметь экземпляров
    }
}
```

## Пошаговое объяснение
1. `IPrintable` объявляет свойство `Title` (только чтение) и метод `Print`; реализаций в интерфейсе нет.
2. `Book` и `Car` не связаны наследованием, но оба заявляют `: IPrintable` и обязаны реализовать все члены.
3. Метод `Show` принимает `IPrintable` и работает через общий договор, не зная, что перед ним — книга или автомобиль.
4. Массив `IPrintable[]` хранит объекты разных классов; создать объект самого интерфейса нельзя (`CS0144`).

## Трассировка и проверка
| Элемент `IPrintable[]` | Тип | Вывод |
|--:|---|---|
| 0 | Book | [Алгоритмы] Книга: Алгоритмы |
| 1 | Car | [Nexia] Автомобиль: Nexia |

Метод `Show(IPrintable)` работает с обоими типами, ничего о них не зная. `new IPrintable()` — `CS0144`.

## Результат
Для книги и автомобиля выведены заголовки и описания; new IPrintable() не компилируется (CS0144).

## Типичные ошибки
- Забыть реализовать член интерфейса (`CS0535`).
- Реализовать с неверной сигнатурой.
- Делать член не `public` при неявной реализации (`CS0737`).
- Использовать интерфейс там, где нужно общее состояние (лучше абстрактный класс).

- Объявить интерфейс с методом по умолчанию (C# 8).
