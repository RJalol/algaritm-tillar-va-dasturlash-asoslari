# L15. Метод с параметрами массива и `params`. Модификаторы `ref` и `out`

Практические задания к теме №15 дисциплины «Алгоритмические языки и программирование» (версия V3).

## Особенность этой темы

Тема №13 оставила без ответа вопрос: как заставить метод **изменить** переданную ему переменную. Метод `Swap` не работал. Тема №15 снимает это ограничение — и вместе с тем даёт понятие, без которого объяснение невозможно: различие **значимых** и **ссылочных** типов.

Центральное задание темы — ALG-014 и ALG-029. Они показывают, что для параметра ссылочного типа существуют **две разные** операции с разным результатом:

| Операция | Видна вызывающему коду? |
|---|---|
| `a[0] = 100;` — изменение элемента | **да** |
| `a = new int[3];` — переприсваивание параметра | **нет** |
| то же с модификатором `ref` | **да** |

Не используются: модификаторы `in` и `ref readonly`, кортежи значений, **перегрузка методов** (тема №17), **структуры** (тема №18), **классы** (тема №16). Различие значимых и ссылочных типов даётся вводно; полное рассмотрение — тема №18.

## Ключевые идеи темы, проверяемые заданиями

- Для значимых типов копируется **значение**, для ссылочных — **ссылка** (ALG-005, ALG-014, ALG-029).
- `ref` требует, чтобы аргумент был **инициализирован до вызова** (`CS0165`), и записывается и в объявлении, и в вызове: пропуск даёт `CS1620`, лишнее указание — `CS1615` (ALG-016, ALG-017, ALG-021).
- `out` **не** требует инициализации аргумента, но обязывает метод присвоить значение на **всех** путях исполнения — иначе `CS0177` (ALG-018, ALG-021, ALG-030).
- Приём `TryXxx`: логический признак успеха плюс результат через `out`; при неудаче параметр всё равно получает значение (`0` для `int`), и обращаться к нему до проверки признака нельзя (ALG-007–009, ALG-022, ALG-027, ALG-028).
- `params` допускает **ни одного** аргумента: метод получает массив нулевой длины, а не `null` (ALG-004, ALG-020).
- Параметр `params` обязан быть **последним** (`CS0231`) и иметь тип коллекции (`CS0225`); необязательный параметр может стоять непосредственно перед ним (ALG-019, ALG-024).
- Строку изменяет через `ref` даже при том, что `string` — ссылочный тип: методы строк возвращают **новую** строку, то есть выполняется переприсваивание (ALG-013).

## О диагностических заданиях

Задания Middle ALG-014, ALG-016–ALG-020 и Advanced ALG-021, ALG-029, ALG-030 содержат код для анализа: найти ошибку, назвать её код либо предсказать вывод до запуска.

Все коды сообщений (`CS0165`, `CS0177`, `CS0225`, `CS0231`, `CS1615`, `CS1620`) и **все числовые ответы** (`8 3` после `Swap`; `min=-5 max=17`; `0`, `1`, `10` и `18` для `Sum`; `3 1 2` после круговой перестановки; `30` при накоплении; `1 2 3 0 0` после увеличения массива; удач 2, неудач 4, сумма 1598) проверены фактической компиляцией и запуском на .NET 8 с культурой ru-RU.

## Формат каждого задания (V3)

Каждый файл `L15-ALG-XXX.md` содержит только два поля: **Условие** и **Ожидаемый результат**. **Готовые решения не приводятся.**

## Материалы для подготовки

Перед выполнением заданий рекомендуется изучить лекцию по теме №15: значимые и ссылочные типы (вводно), массив как параметр метода, различие изменения содержимого и переприсваивания параметра, модификаторы `ref` и `out`, приём `TryXxx`, ключевое слово `params` и его ограничения, выбор между `ref`, `out` и возвращаемым значением.
