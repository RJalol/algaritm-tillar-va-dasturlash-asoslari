# L17. Перегрузка методов и конструкторов. Класс Program и метод Main. Свойства

Практические задания к теме №17 дисциплины «Алгоритмические языки и программирование» (версия V3).

## Особенность этой темы

Тема №16 оставила два ограничения: класс имел ровно **один** конструктор, а поля были открыты для прямого присваивания — запись `s.Score = 200` портила объект в обход всех проверок. Тема №17 устраняет оба.

Центральный результат темы — **свойство с проверкой**: присваивание `s.Score = 200` теперь проходит без ошибки и без исключения, но поле получает `100`.

Самая опасная ошибка темы не имеет ни кода компилятора, ни предупреждения:

```
public int Score
{
    get { return Score; }   // обращение к самому себе
    set { Score = value; }
}
```

Фрагмент компилируется безупречно, а при первом же обращении процесс завершается сообщением `Stack overflow.` — та же ошибка, что и рекурсия без базового случая из темы №14, только записанная неочевидным образом (задания ALG-020 и ALG-030).

Не используются: **деструкторы** (тема №38), модификаторы доступа для отдельных методов доступа и `init` (тема №19), **структуры** (тема №18), **статические члены** (тема №20), **перегрузка операторов** (тема №22), **наследование** (темы №24–26), операторы верхнего уровня и `async`.

> ⚠ **Задания ALG-020 и ALG-030 запускать не следует** — они содержат рекурсивное свойство и решаются анализом.

## Ключевые идеи темы, проверяемые заданиями

- Перегрузки различаются **числом** или **типами** параметров; ни тип результата, ни имена параметров их не различают — `CS0111` (ALG-016, ALG-017, ALG-021, ALG-030).
- Если ни одна перегрузка не лучше остальных — `CS0121` (ALG-018, ALG-021).
- При отсутствии точного соответствия компилятор применяет неявное преобразование: `Show(42L)` при перегрузках `int`/`double` выбирает **`double`** (ALG-011, ALG-029).
- Запись `: this(...)` вызывает другой конструктор того же класса; **тело вызываемого выполняется первым** (ALG-010, ALG-026).
- `Main` объявляется внутри класса, обязан быть `static`, возвращает `void` или `int`; массив `args` **никогда не равен `null`** и при отсутствии аргументов имеет длину 0 (ALG-014, ALG-015).
- Свойство с проверкой в методе `set` не допускает недопустимого состояния объекта — но только если конструктор присваивает **свойству**, а не полю (ALG-006, ALG-009).
- Автоматическое свойство без `set` присваивается **только из конструкторов типа**; присваивание извне — `CS0200` (ALG-008, ALG-019).
- Вычисляемое свойство хранилища не имеет и вычисляется при каждом обращении (ALG-007, ALG-023, ALG-027).
- Переход от открытого поля к свойству **не требует** изменения вызывающего кода (ALG-025, ALG-028).

## О диагностических заданиях

Задания Middle ALG-011, ALG-016–ALG-020 и Advanced ALG-021, ALG-029, ALG-030 содержат код для анализа: найти ошибку, назвать её код либо предсказать выбор перегрузки до запуска.

Все коды сообщений (`CS0111`, `CS0121`, `CS0200`), поведение рекурсивного свойства и **все числовые ответы** (`1x1`, `4x4`, `3x5` и площадь 16; баллы 87, 100, 0 и 95; `0,00 UZS`, `1500,50 UZS` и `20,00 USD`; температуры `100,00 C = 212,00 F = 373,15 K` и `-273,15 C = -459,67 F = 0,00 K`; время `23:50`, `00:15` и `01:15`; выбор перегрузок `int`, `long`, `double`, `double`, `int`, `object`) проверены фактической компиляцией и запуском на .NET 8 с культурой ru-RU.

## Формат каждого задания (V3)

Каждый файл `L17-ALG-XXX.md` содержит только два поля: **Условие** и **Ожидаемый результат**. **Готовые решения не приводятся.**
