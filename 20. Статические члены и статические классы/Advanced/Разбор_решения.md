# Разбор решения. L20-ALG-021. Восемь нарушений в одном фрагменте

## Условие
Дан код:

```
static class Util
{
    public int Field;
    public void Method() { }
    public Util() { }
    public static int Ok() { return 1; }
}

class Counter
{
    public static int Total;
    public int Value;
    public static int Bad() { return Value; }
}

class Ctor
{
    public static int X;
    public static Ctor(int a) { X = a; }
}

Util u = new Util();
Counter c = new Counter();
Console.WriteLine(c.Total);
```

Найти все нарушения, назвать код ошибки для каждого и разнести их по трём группам: ограничения статического класса; ограничения статического конструктора; смешение уровня типа и уровня экземпляра. Привести исправленный фрагмент.

## Ожидаемый результат
Названы коды `CS0708` (дважды), `CS0710`, `CS0712`, `CS0723`, `CS0132`, `CS0515`, `CS0120` и `CS0176`; группы разнесены верно; отмечено, что одна строка `Util u = new Util();` даёт **два** разных кода.

## Разбор условия
**Дано:** три фрагмента со статическими классами, статическим конструктором и смешением статического и экземплярного.
**Требуется:** найти нарушения, назвать коды (`CS0708` ×2, `CS0710`, `CS0712`, `CS0723`, `CS0132`, `CS0515`, `CS0120`, `CS0176`), разнести по группам.

## Теоретическая справка
Группы правил:

1. **Статический класс:** только статические члены (`CS0708`), нет конструкторов экземпляра (`CS0710`), нельзя создать экземпляр (`CS0712`) и объявить переменную такого типа (`CS0723`).
2. **Статический конструктор:** вызывается автоматически один раз, поэтому не может иметь параметров (`CS0132`) и модификаторов доступа (`CS0515`).
3. **Уровень типа и уровень экземпляра:** статический метод не имеет `this` и не видит экземплярных полей (`CS0120`); статический член нельзя вызывать через экземпляр (`CS0176`).

Строка `Util u = new Util();` даёт сразу два сообщения: `CS0723` (переменная статического типа) и `CS0712` (создание экземпляра).

## Идея решения
Для каждого члена проверяем: можно ли ему быть в статическом классе, допустим ли конструктор с параметрами у статического и можно ли из статического метода обратиться к экземплярному члену.

## Решение
```csharp
// Исправленный фрагмент
static class Util
{
    public static int Field;                 // члены статического класса - статические
    public static void Method() { }
    public static int Ok() { return 1; }
}
class Counter
{
    public static int Total;
    public int Value;
    public static int Bad() { return Total; }   // из static-метода - только static-члены
}
class Ctor
{
    public static int X;
    static Ctor() { X = 1; }                     // статический конструктор без параметров и модификатора доступа
}
// Util u = new Util();       // создать экземпляр статического класса нельзя
Counter c = new Counter();
Console.WriteLine(Counter.Total);                // к статическому члену - через класс
```

## Пошаговое объяснение
1. Ограничения статического класса: нестатические поле, метод, конструктор — `CS0708` (дважды) и `CS0710`.
2. Ограничения статического конструктора: модификатор доступа (`CS0515`) и параметры (`CS0132`).
3. Смешение уровней: `return Value;` в статическом методе — обращение к экземплярному полю (`CS0120`); `c.Total` — статический член нельзя читать через объект (`CS0176`).
4. Строка `Util u = new Util();` даёт два кода: `CS0723` (переменная статического типа) и `CS0712` (создание экземпляра статического класса).

## Трассировка и проверка
| Код | Нарушение |
|---|---|
| CS0708 | нестатическое поле и метод в статическом классе |
| CS0710 | конструктор экземпляра в статическом классе |
| CS0712 | `new Util()` |
| CS0723 | переменная типа `Util` |
| CS0132 | `static Ctor(int a)` — параметры |
| CS0515 | `public static Ctor` — модификатор доступа |
| CS0120 | `Value` в статическом методе |
| CS0176 | `c.Total` через экземпляр |

Исправленный фрагмент использует `static`-члены, `Counter.Total`, `static Ctor()`.

## Результат
Названы коды CS0708 (×2), CS0710, CS0712, CS0723, CS0132, CS0515, CS0120, CS0176; строка new Util() порождает два кода.

## Типичные ошибки
- Забывать, что каждый член статического класса должен быть `static`.
- Пытаться передать параметры статическому конструктору.
- Обращаться к экземплярным полям из статического метода.
- Читать статическое поле через объект.
