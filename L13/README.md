# L13. Собственные методы. Основы тестирования программ

Практические задания к теме №13 дисциплины «Алгоритмические языки и программирование» (версия V3).

## Особенность этой темы

Первые двенадцать тем строились на одном допущении: вся программа помещается в метод `Main`. Тема №13 снимает это допущение — и вместе с ним даёт первый систематический ответ на вопрос: **как убедиться, что написанный код работает правильно**.

Эти две половины темы связаны не случайно. Метод с параметрами и результатом можно испытать **отдельно** от остальной программы — именно это и делает тестирование возможным.

Задание ALG-023 показывает, зачем нужны граничные тест-кейсы: метод `Factorial` правильно вычисляет 20! = `2432902008176640000`, но для 21 **молча** возвращает отрицательное число `-4249290049419214848`. Ни компилятор, ни среда выполнения об этом не сообщают.

Не используются: **перегрузка методов** (тема №17), **модификаторы параметров** `ref`, `out`, `params` (темы №14–15), **рекурсия** (тема №14), отдельные библиотеки модульного тестирования. Все методы объявляются со словом `static`.

## Ключевые идеи темы, проверяемые заданиями

- Метод с типом, отличным от `void`, обязан возвращать значение на **всех** путях — иначе `CS0161` (ALG-016, ALG-021, ALG-030).
- В методе `void` `return` записывается без выражения; `return` со значением даёт `CS0127` (ALG-017, ALG-021).
- Число, порядок и типы аргументов должны соответствовать параметрам: `CS7036`, `CS1501`, `CS1503` (ALG-018, ALG-021).
- Локальная переменная существует только внутри своего метода — `CS0103`; совпадение имён в разных методах ошибкой **не является** (ALG-019, ALG-029).
- Вызов нестатического метода из `Main` даёт `CS0120` (ALG-021).
- Значимые типы передаются **по значению**: метод `Swap` с обычными параметрами ничего не меняет (ALG-014, ALG-030). Массив — ссылочный тип, и изменение его элементов видно снаружи (ALG-015).
- Вызов, результат которого отброшен, компилируется **без предупреждений** (ALG-021, ALG-030).
- Ожидаемый результат тест-кейса определяется **из условия задачи**, а не запуском проверяемой программы (ALG-022).
- Ошибки сосредоточены на **границах**: пары значений вокруг каждого порога и пределы диапазона типа (ALG-022, ALG-023, ALG-030).
- `Debug.Assert` помечен атрибутом `Conditional("DEBUG")` и **полностью удаляется** в конфигурации Release; данные пользователя проверяются оператором `if` (ALG-024, ALG-026).

## О диагностических заданиях

Задания Middle ALG-014–ALG-019 и Advanced ALG-021, ALG-023, ALG-024, ALG-029, ALG-030 содержат код для анализа: найти ошибку, назвать её код либо предсказать вывод до запуска.

Все коды сообщений (`CS0103`, `CS0120`, `CS0127`, `CS0161`, `CS1501`, `CS1503`, `CS7036`), поведение `Debug.Assert` в обеих конфигурациях и **все числовые ответы** (`Square(Square(3))` = 81; простые до 20; факториалы 0, 1, 5, 10, 20 и переполнение при 21; НОД 6, 1, 7, 12; суммы цифр 15, 0, 11; площадь круга 12,5664; `Max` на отрицательных данных) проверены фактической компиляцией и запуском на .NET 8 с культурой ru-RU.

## Формат каждого задания (V3)

Каждый файл `L13-ALG-XXX.md` содержит только два поля: **Условие** и **Ожидаемый результат**. **Готовые решения не приводятся.**

## Материалы для подготовки

Перед выполнением заданий рекомендуется изучить лекцию по теме №13: назначение методов, сигнатура, возвращаемое значение и оператор `return`, методы типа `void`, параметры и аргументы, локальные переменные и область видимости, передача по значению, понятие тест-кейса, граничные случаи, проверки `Debug.Assert`.
