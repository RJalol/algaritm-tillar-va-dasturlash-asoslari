# Разбор решения. L30 · Задание II · №1. Копирование файла блоками

## Условие
Скопировать файл через два `FileStream`, читая блоками по 4096 байт.

## Ожидаемый результат
Копия побайтово совпадает с оригиналом.

## Разбор условия
**Дано:** исходный файл.
**Требуется:** скопировать его через два `FileStream`, читая блоками по 4096 байтов; сравнить размеры.

## Теоретическая справка
**Потоковая обработка** читает и пишет данные порциями фиксированного размера — память не зависит от размера файла.

Метод `Read(buffer, offset, count)` возвращает число **фактически прочитанных** байтов (может быть меньше `count`), а в конце потока — 0. Записывать следует ровно столько, сколько прочитано: `Write(buffer, 0, read)`.

Размер буфера — компромисс: слишком малый увеличивает число системных вызовов, слишком большой расходует память. Типичные значения — 4–80 КБ.

## Идея решения
Копирование блоками: читаем из исходного потока порцию байтов в буфер и сразу записываем ровно столько, сколько прочитали. Цикл заканчивается, когда `Read` вернул 0.

## Решение
```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string source = "source.bin";
        string target = "copy.bin";
        byte[] buffer = new byte[4096];

        using (FileStream input = new FileStream(source, FileMode.Open, FileAccess.Read))
        using (FileStream output = new FileStream(target, FileMode.Create, FileAccess.Write))
        {
            int read;
            while ((read = input.Read(buffer, 0, buffer.Length)) > 0)
            {
                output.Write(buffer, 0, read);   // записываем только прочитанное
            }
        }

        Console.WriteLine("Исходный: " + new FileInfo(source).Length + " Б");
        Console.WriteLine("Копия:    " + new FileInfo(target).Length + " Б");
    }
}
```

## Пошаговое объяснение
1. Буфер на 4096 байт позволяет копировать файлы любого размера, не загружая их в память целиком.
2. `Read` возвращает число реально прочитанных байтов; в последней порции оно меньше размера буфера, поэтому записывать нужно `read` байтов, а не `buffer.Length`.
3. Когда файл закончился, `Read` возвращает 0 и цикл завершается.
4. Оператор `using` гарантирует закрытие обоих потоков даже при исключении.
5. Совпадение размеров подтверждает копирование (для проверки содержимого можно сравнить файлы побайтово).

## Трассировка и проверка
Файл 10 000 байт, буфер 4096:

| Итерация | read | Записано |
|--:|--:|--:|
| 1 | 4096 | 4096 |
| 2 | 4096 | 4096 |
| 3 | 1808 | 1808 |
| 4 | 0 | цикл завершён |

Итого 10 000 — размер копии равен размеру оригинала.

## Результат
Размеры исходного файла и копии совпадают; копия побайтово идентична оригиналу.

## Типичные ошибки
- Записывать `buffer.Length` вместо `read` — в копии окажется мусор в конце.
- Предполагать, что один `Read` читает весь файл.
- Не закрыть потоки.
- Открыть исходный файл в режиме записи.
