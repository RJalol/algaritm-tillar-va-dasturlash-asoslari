# Разбор решения. L28 · Задание III · №1. Собственный класс исключения

## Условие
Создать класс `InsufficientFundsException : Exception` с полями «баланс» и «запрошенная сумма», тремя стандартными конструкторами. Использовать в классе «банковский счёт».

## Ожидаемый результат
При снятии суммы больше остатка выбрасывается собственное исключение с нужными данными.

## Разбор условия
**Дано:** банковский счёт.
**Требуется:** собственное исключение `InsufficientFundsException` с данными (баланс, запрошенная сумма) и стандартными конструкторами; выбрасывать при недостатке средств.

## Теоретическая справка
**Собственные исключения** создают, когда стандартные типы не выражают ошибку предметной области. Рекомендации:

- наследовать от `Exception` (или `ApplicationException`/`InvalidOperationException`, если уместно);
- имя заканчивается на `Exception`;
- предусмотреть три стандартных конструктора: без аргументов, с сообщением, с сообщением и внутренним исключением;
- хранить в свойствах данные, нужные обработчику.

**Блок `finally`** выполняется всегда — при успехе, при исключении, при `return` — и предназначен для освобождения ресурсов.

## Идея решения
Собственное исключение наследуется от `Exception`, содержит дополнительные данные (баланс, запрошенная сумма) и три стандартных конструктора. Класс «счёт» выбрасывает его при недостатке средств.

## Решение
```csharp
using System;

class InsufficientFundsException : Exception
{
    public decimal Balance { get; }
    public decimal Requested { get; }

    public InsufficientFundsException() { }

    public InsufficientFundsException(string message) : base(message) { }

    public InsufficientFundsException(string message, Exception inner) : base(message, inner) { }

    public InsufficientFundsException(decimal balance, decimal requested)
        : base($"Недостаточно средств: на счёте {balance}, запрошено {requested}")
    {
        Balance = balance;
        Requested = requested;
    }
}

class BankAccount
{
    public decimal Balance { get; private set; }

    public BankAccount(decimal balance) { Balance = balance; }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        if (amount > Balance) throw new InsufficientFundsException(Balance, amount);
        Balance -= amount;
    }
}

class Program
{
    static void Main()
    {
        BankAccount acc = new BankAccount(1000);
        try
        {
            acc.Withdraw(300);
            Console.WriteLine("Остаток: " + acc.Balance);
            acc.Withdraw(900);
        }
        catch (InsufficientFundsException e)
        {
            Console.WriteLine(e.Message);
            Console.WriteLine("Не хватает: " + (e.Requested - e.Balance));
        }
        finally
        {
            Console.WriteLine("Операция завершена");
        }
    }
}
```

## Пошаговое объяснение
1. Класс `InsufficientFundsException : Exception` содержит свойства `Balance` и `Requested`, чтобы обработчик мог получить контекст ошибки.
2. Три стандартных конструктора (без аргументов, с сообщением, с сообщением и внутренним исключением) — принятая практика для исключений.
3. Метод `Withdraw` проверяет условия *до* изменения состояния и выбрасывает исключение, не изменяя баланс.
4. В `catch` доступны и сообщение, и данные: можно вывести, сколько не хватает.
5. Блок `finally` выполняется в любом случае.

## Трассировка и проверка
Сценарий: баланс 1000.

| Операция | Результат |
|---|---|
| `Withdraw(300)` | остаток 700 |
| `Withdraw(900)` | `InsufficientFundsException(700, 900)` |

В `catch`: сообщение «Недостаточно средств: на счёте 700, запрошено 900» и «Не хватает: 200». В `finally`: «Операция завершена». Баланс после неудачной операции остаётся 700 — проверка выполняется *до* изменения состояния.

## Результат
Остаток: 700 / Недостаточно средств: на счёте 700, запрошено 900 / Не хватает: 200 / Операция завершена

## Типичные ошибки
- Менять состояние до проверки (после исключения объект остаётся «наполовину изменённым»).
- Использовать собственное исключение для обычных ситуаций, где достаточно возврата `false`.
- Не хранить данные ошибки в свойствах (обработчик вынужден разбирать текст сообщения).
- Терять внутреннее исключение при повторном выбрасывании.
