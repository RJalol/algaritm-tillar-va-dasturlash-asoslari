# Разбор решения. L04-ALG-021. Три нарушения в одном фрагменте

## Условие
Дан код:

```
byte total = 200;
total = total + 100;
bool ready = true;
int flag = ready + 1;
int share = 10 / (3 / 5);
```

Найти все нарушения, для каждого назвать код ошибки компилятора и объяснить причину отдельно. Указать, какое из трёх нарушений связано с преобразованием типов, какое — с применимостью операции, а какое — с вычислением константного выражения.

## Ожидаемый результат
Три независимых нарушения с кодами `CS0266`, `CS0019` и `CS0020`; для третьего объяснено, что внутреннее выражение `3 / 5` даёт нулевую константу и деление на неё обнаруживается уже на этапе компиляции.

## Разбор условия
**Дано:** фрагмент из пяти строк.
**Требуется:** найти три нарушения, назвать код ошибки компилятора для каждого и отнести: преобразование типов, применимость операции, вычисление константного выражения.

## Теоретическая справка
Три вида ошибок:

1. **Сужающее преобразование:** результат выражения `byte + int` имеет тип `int` (все арифметические операции над типами, меньшими `int`, выполняются в `int`). Присвоить `int` переменной `byte` без явного приведения нельзя — возможна потеря данных (`CS0266`).
2. **Применимость операции:** операция `+` не определена для пары `bool` и `int` (`CS0019`) — в C# нет неявного перехода между логическим и числовым типами.
3. **Константное выражение:** выражение из одних литералов вычисляется при компиляции. Если в нём встречается деление целых на нуль, то это ошибка компиляции (`CS0020`).

## Идея решения
Каждую строку проверяем на соответствие правилам типов и константных выражений.

## Решение
```csharp
// Исправленный фрагмент
byte total = 200;
total = (byte)(total + 100);    // явное приведение (результат переполнится!)
bool ready = true;
int flag = ready ? 1 : 0;       // bool не складывается с числом
int share = 10 / (3 / 5 + 1);   // знаменатель не равен нулю
```

## Пошаговое объяснение
1. `total = total + 100;` — в выражении `byte + int` результат имеет тип `int`; неявно сузить его до `byte` нельзя (`CS0266`). Это нарушение преобразования типов.
2. `ready + 1` — операция `+` не определена для `bool` и `int` (`CS0019`). Это нарушение применимости операции.
3. `10 / (3 / 5)` — выражение `3 / 5` целочисленное и равно 0; значит, делим на константу 0, что компилятор обнаруживает при компиляции (`CS0020`). Это нарушение вычисления константного выражения.
4. Исправления: явное приведение (с осознанием возможной потери данных), условный оператор для перевода `bool` в число, корректный знаменатель.

## Трассировка и проверка
Анализ третьей строки пошагово: `3 / 5` — целочисленное деление, результат `0`. Выражение `10 / (3 / 5)` превращается в `10 / 0` — деление на константный нуль, которое компилятор обнаруживает сам.

Исправленный вариант проверяется мысленной компиляцией: `total = (byte)(total + 100)` — приведение допустимо, но результат 300 не помещается в `byte` и станет 44 (потеря старших битов); `ready ? 1 : 0` — корректное преобразование `bool` в число; `10 / (3 / 5.0)` или иное ненулевое выражение — деление выполнимо.

## Результат
Три нарушения: CS0266, CS0019, CS0020; в третьем 3 / 5 даёт константу 0, и деление на неё ловится на этапе компиляции.

## Типичные ошибки
- Считать, что `byte + byte` даёт `byte` — на самом деле `int`.
- Полагать, что деление на ноль всегда обнаруживается только во время выполнения; для констант оно ловится при компиляции.
- Исправлять ошибку приведением без анализа последствий (молчаливое усечение).
- Складывать `bool` и число по аналогии с другими языками (C, C++).
