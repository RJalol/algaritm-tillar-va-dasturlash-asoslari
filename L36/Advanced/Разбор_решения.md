# Разбор решения. L36 · Задание III · №1. Конвейер обработки

## Условие
Реализовать конвейер: коллекция делегатов `Func<string,string>` (обрезка пробелов, верхний регистр, замена, добавление префикса), применяемых по очереди к строке.

## Ожидаемый результат
Результат обработки строки соответствует последовательному применению всех шагов.

## Разбор условия
**Дано:** строка и набор шагов обработки.
**Требуется:** конвейер из делегатов `Func<string,string>`, применяемых по очереди.

## Теоретическая справка
**Конвейер (pipeline)** — последовательное применение функций: результат предыдущей — вход следующей. Математически это композиция функций: f₄(f₃(f₂(f₁(x)))).

В коде конвейер хранится в списке делегатов; метод `Aggregate(seed, (acc, f) => f(acc))` свёртывает список в одно значение, подставляя результат предыдущего шага.

Достоинства: шаги независимы, их легко добавлять, переставлять, тестировать отдельно. Это основа промежуточного ПО (middleware) в веб-приложениях.

## Идея решения
Конвейер — список шагов, каждый из которых является делегатом `Func<string,string>`. Результат одного шага подаётся на вход следующему; для обхода используем `Aggregate`.

## Решение
```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Program
{
    static void Main()
    {
        var pipeline = new List<Func<string, string>>
        {
            s => s.Trim(),
            s => s.ToUpper(),
            s => s.Replace(' ', '_'),
            s => "[" + s + "]"
        };

        string input = "  hello pipeline world ";
        string result = pipeline.Aggregate(input, (current, step) => step(current));

        Console.WriteLine(result);
    }
}
```

## Пошаговое объяснение
1. Шаги описываются как лямбда-выражения и хранятся в списке в нужном порядке.
2. `Aggregate(seed, func)` начинает с исходной строки и последовательно применяет каждый шаг к результату предыдущего.
3. Результаты по шагам: `"hello pipeline world"` → `"HELLO PIPELINE WORLD"` → `"HELLO_PIPELINE_WORLD"` → `"[HELLO_PIPELINE_WORLD]"`.
4. Новый шаг добавляется в список без изменения остального кода — это и есть преимущество делегатов.

## Трассировка и проверка
Для `"  hello pipeline world "`:

| Шаг | Результат |
|---|---|
| исходная | `  hello pipeline world ` |
| `Trim` | `hello pipeline world` |
| `ToUpper` | `HELLO PIPELINE WORLD` |
| `Replace(' ', '_')` | `HELLO_PIPELINE_WORLD` |
| префикс/суффикс | `[HELLO_PIPELINE_WORLD]` |

Порядок важен: если поменять местами `Trim` и `Replace`, пробелы по краям превратятся в `_`.

## Результат
[HELLO_PIPELINE_WORLD]

## Типичные ошибки
- Поменять порядок шагов и получить другой результат.
- Изменять общую переменную из шагов вместо возврата значения.
- Не обработать `null` на входе.
- Использовать побочные эффекты в шагах, нарушая предсказуемость.
