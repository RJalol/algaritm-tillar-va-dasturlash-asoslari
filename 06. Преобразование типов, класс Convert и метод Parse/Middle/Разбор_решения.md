# Разбор решения. L06-ALG-006. Потеря старших битов

## Условие
Написать программу, которая объявляет переменную типа `int` со значением 500 и переменную типа `int` со значением 70000, а затем приводит первую к типу `byte`, вторую — к типу `short`, и выводит оба результата. Объяснить в комментарии, почему полученные числа не совпадают с исходными и почему компилятор не выдал предупреждения.

## Ожидаемый результат
Две строки: `244` и `4464`; в комментарии объяснено, что не поместившиеся старшие биты отбрасываются молча, а операция приведения означает принятие этого риска программистом.

## Разбор условия
**Дано:** `int a = 500`, `int c = 70000`.
**Требуется:** привести первое к `byte`, второе к `short`, вывести результаты и объяснить в комментарии, почему числа изменились и почему нет предупреждения.

## Теоретическая справка
При явном **сужающем приведении** в контексте `unchecked` (по умолчанию для неконстантных выражений) отбрасываются старшие биты, не помещающиеся в целевой тип. Это эквивалентно взятию остатка от деления на 2ⁿ, где n — число бит целевого типа:

- для `byte`: результат = значение mod 256;
- для `short`: результат = значение mod 65 536 (с учётом знака).

Явное приведение — заявление программиста: «я знаю о возможной потере». Поэтому компилятор не выдаёт предупреждения.

## Идея решения
При явном приведении к более узкому типу старшие биты, не поместившиеся в целевой тип, отбрасываются (в контексте `unchecked`, действующем по умолчанию).

## Решение
```csharp
using System;

class Program
{
    static void Main()
    {
        int a = 500;
        int c = 70000;

        byte  b = (byte)a;    // 500 mod 256 = 244
        short s = (short)c;   // 70000 - 65536 = 4464

        Console.WriteLine(b);
        Console.WriteLine(s);

        // Старшие биты, не поместившиеся в целевой тип, отбрасываются молча.
        // Явная операция приведения означает, что программист принимает риск,
        // поэтому компилятор не выдаёт ни ошибки, ни предупреждения.
    }
}
```

## Пошаговое объяснение
1. 500 в двоичном виде — `1 1111 0100`; в `byte` помещаются младшие 8 бит `1111 0100` = 244.
2. 70000 = 65536 + 4464; в `short` (16 бит) остаётся младшая часть 4464 (значение лежит в диапазоне −32768…32767, поэтому знак не меняется).
3. Приведение — явная команда программиста, поэтому компилятор доверяет ему и не предупреждает о потере.
4. Если нужен контроль, используют `checked` — тогда вместо молчаливой потери возникнет `OverflowException`.

## Трассировка и проверка
Расчёты:

- 500 = 1·256 + 244 → `(byte)500 = 244`. Двоично: `1 1111 0100` → младшие 8 бит `1111 0100` = 244.
- 70000 = 1·65536 + 4464 → `(short)70000 = 4464` (значение в пределах −32768…32767, знак не меняется).

Проверка контекстом `checked`: `checked((byte)a)` выбросит `OverflowException` — так можно превратить молчаливую потерю в обнаруживаемую ошибку.

## Результат
Выводятся 244 и 4464.

## Типичные ошибки
- Ожидать ошибки компиляции — для неконстантных выражений её нет.
- Считать результат «ближайшим значением» (saturation): C# не ограничивает значение, а отбрасывает биты.
- Использовать приведение константы `(byte)500` (это ошибка `CS0221`, пока не указан `unchecked`).
- Не включать `checked` там, где потеря данных недопустима.
