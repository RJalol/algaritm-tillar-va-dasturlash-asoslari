# Разбор решения. L06-ALG-021. Три нарушения в одном фрагменте

## Условие
Дан код:

```
double real = 3.9;
int whole = real;
int? maybe = 42;
int definite = maybe;
byte small = (byte)500;
```

Найти все нарушения, для каждого назвать код ошибки компилятора и объяснить причину отдельно. Для третьего нарушения дополнительно указать, при каком изменении кода оно исчезнет, хотя проблема по существу останется. Привести исправленный фрагмент.

## Ожидаемый результат
Три нарушения с кодами `CS0266`, `CS0266` и `CS0221`; для третьего указано, что замена литерала на переменную того же значения снимает ошибку компиляции, но приводит к молчаливой потере данных.

## Разбор условия
**Дано:** фрагмент из трёх групп операторов с преобразованием `double → int`, `int? → int`, константой `(byte)500`.
**Требуется:** найти три нарушения, назвать коды, объяснить; для третьего — что изменит вид ошибки; привести исправленный фрагмент.

## Теоретическая справка
Три разных механизма:

- **`double → int`** — сужающее, всегда требует явного приведения, при котором дробная часть **отбрасывается** (3,9 → 3), а не округляется.
- **`int? → int`** — преобразование обнуляемого типа в базовый требует явной операции, потому что значение может отсутствовать. Варианты: `maybe.Value` (исключение при `null`), `(int)maybe`, `maybe ?? 0`, `maybe.GetValueOrDefault()`.
- **Константное выражение `(byte)500`** вычисляется компилятором; значение вне диапазона в контексте `checked` (для констант — по умолчанию) — ошибка `CS0221`. Подавить её можно оператором `unchecked(...)`.

## Идея решения
Проверяем, где требуется явное приведение, где нужно обратиться к значению `Nullable`, и что происходит с константами вне диапазона.

## Решение
```csharp
// Исправленный фрагмент
double real = 3.9;
int whole = (int)real;               // 3, дробная часть отбрасывается
int? maybe = 42;
int definite = maybe.Value;          // или (int)maybe, или maybe ?? 0
byte small = unchecked((byte)500);   // 244: потеря данных осознанна
```

## Пошаговое объяснение
1. `int whole = real;` — `double` в `int` неявно не преобразуется, возможна потеря данных (`CS0266`); нужно явное приведение `(int)real`.
2. `int definite = maybe;` — `int?` в `int` неявно не преобразуется, так как значение может отсутствовать (`CS0266`); используем `.Value`, явное приведение или `??`.
3. `(byte)500` — константа 500 не помещается в `byte`; компилятор при вычислении константного выражения сообщает об ошибке (`CS0221`), пока не указан `unchecked`.
4. Замена литерала на переменную (`int n = 500; byte x = (byte)n;`) снимает ошибку компиляции, но проблема остаётся: значение молча превратится в 244.

## Трассировка и проверка
| Строка | Что произойдёт | Код |
|---|---|---|
| `int whole = real;` | нет неявного `double → int` | CS0266 |
| `int definite = maybe;` | нет неявного `int? → int` | CS0266 |
| `byte small = (byte)500;` | константа вне диапазона | CS0221 |

Если записать `int n = 500; byte x = (byte)n;`, то ошибка компиляции пропадает — компилятор больше не знает значение заранее. Но данные при этом теряются молча (результат 244). Поэтому «исчезновение ошибки» не равносильно исправлению.

## Результат
Нарушения: CS0266, CS0266, CS0221; в третьем замена константы на переменную убирает ошибку, но приводит к молчаливой потере данных.

## Типичные ошибки
- Ожидать округления при `(int)3.9` (на самом деле 3; для округления есть `Math.Round`).
- Использовать `maybe.Value` без проверки `HasValue` — исключение `InvalidOperationException`.
- Заменять константу переменной ради «заглушки» ошибки.
- Забывать, что `unchecked` скрывает проблему, а не решает её.
