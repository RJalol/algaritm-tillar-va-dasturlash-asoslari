# Разбор решения. L38 · Задание III · №2. Банковский счёт с оповещениями

## Условие
Реализовать банковский счёт с событиями `Deposited`, `Withdrawn`, `LowBalance` и подписчиками «СМС», «Журнал».

## Ожидаемый результат
Каждая операция порождает нужные события.

## Разбор условия
**Дано:** банковский счёт.
**Требуется:** события `Deposited`, `Withdrawn`, `LowBalance`; подписчики «СМС» и «Журнал»; демонстрация последовательности.

## Теоретическая справка
**Шаблон «Наблюдатель» (Observer).** Издатель не знает конкретных подписчиков — это ослабляет связь и позволяет добавлять реакции без изменения счёта.

Критические моменты:

- события вызываются *после* изменения состояния, когда оно согласовано;
- обработчик, выбросивший исключение, прерывает цепочку вызовов (остальные не вызываются);
- подписчики должны отписываться, когда больше не нужны.

Три события отражают три независимых факта; `LowBalance` — производное: он порождается условием после `Withdraw`.

## Идея решения
Счёт — издатель событий `Deposited`, `Withdrawn`, `LowBalance`. Подписчики («СМС», «Журнал») независимы от счёта и получают данные через аргументы события.

## Решение
```csharp
using System;
using System.Collections.Generic;

class AccountEventArgs : EventArgs
{
    public decimal Amount { get; }
    public decimal Balance { get; }
    public AccountEventArgs(decimal amount, decimal balance) { Amount = amount; Balance = balance; }
}

class Account
{
    private decimal _balance;
    private const decimal LowLimit = 100;

    public event EventHandler<AccountEventArgs> Deposited;
    public event EventHandler<AccountEventArgs> Withdrawn;
    public event EventHandler<AccountEventArgs> LowBalance;

    public void Deposit(decimal amount)
    {
        _balance += amount;
        Deposited?.Invoke(this, new AccountEventArgs(amount, _balance));
    }

    public void Withdraw(decimal amount)
    {
        if (amount > _balance)
            throw new InvalidOperationException("Недостаточно средств");
        _balance -= amount;
        Withdrawn?.Invoke(this, new AccountEventArgs(amount, _balance));
        if (_balance < LowLimit)
            LowBalance?.Invoke(this, new AccountEventArgs(amount, _balance));
    }
}

class SmsNotifier
{
    public void Subscribe(Account a)
    {
        a.LowBalance += (s, e) => Console.WriteLine($"СМС: низкий остаток {e.Balance}");
    }
}

class Journal
{
    public List<string> Lines { get; } = new List<string>();

    public void Subscribe(Account a)
    {
        a.Deposited += (s, e) => Lines.Add($"Пополнение {e.Amount}, остаток {e.Balance}");
        a.Withdrawn += (s, e) => Lines.Add($"Снятие {e.Amount}, остаток {e.Balance}");
    }
}

class Program
{
    static void Main()
    {
        Account acc = new Account();
        Journal journal = new Journal();
        new SmsNotifier().Subscribe(acc);
        journal.Subscribe(acc);

        acc.Deposit(500);
        acc.Withdraw(350);
        acc.Withdraw(60);

        journal.Lines.ForEach(Console.WriteLine);
    }
}
```

## Пошаговое объяснение
1. Счёт публикует три события и не знает, кто на них подписан — слабая связность.
2. Событие `LowBalance` вызывается после снятия, если остаток ниже лимита 100.
3. Подписчик «СМС» реагирует только на низкий остаток, «Журнал» записывает пополнения и снятия.
4. Последовательность: пополнение 500 → остаток 500; снятие 350 → 150; снятие 60 → 90 (ниже лимита, срабатывает `LowBalance`).
5. Журнал после выполнения содержит три записи.

## Трассировка и проверка
Ход: пополнение 500 → снятие 350 → снятие 60.

| Операция | Остаток | События |
|---|--:|---|
| `Deposit(500)` | 500 | Deposited |
| `Withdraw(350)` | 150 | Withdrawn |
| `Withdraw(60)` | 90 | Withdrawn, LowBalance (90 < 100) |

Журнал содержит три записи; «СМС» сработает один раз — при остатке ниже лимита.

## Результат
СМС: низкий остаток 90, затем журнал: Пополнение 500, остаток 500 / Снятие 350, остаток 150 / Снятие 60, остаток 90.

## Типичные ошибки
- Вызывать события до изменения состояния.
- Допускать исключения в обработчиках без защиты.
- Передавать подписчикам изменяемый объект счёта.
- Забывать отписку при уничтожении подписчика.
