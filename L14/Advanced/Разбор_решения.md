# Разбор решения. L14-ALG-021. Пять нарушений в объявлениях и вызовах

## Условие
Дан код:

```
static void Bad1(int a = 1, int b) { }
static void Bad2(int n = DateTime.Now.Year) { }
static void Show(string name, int num, string prod) { }

Show(prod: "X", 31, "Y");
Show("A", 1, wrongName: "Z");
Show("A", num: 1, name: "B");
```

Найти все нарушения, назвать код ошибки для каждого и разнести их по двум группам: ошибки **объявления** метода и ошибки **вызова** метода. Привести исправленный фрагмент.

## Ожидаемый результат
Названы коды `CS1737` и `CS1736` в первой группе, `CS8323`, `CS1739` и `CS1744` — во второй; группы разнесены верно.

## Разбор условия
**Дано:** фрагмент с ошибками объявления и вызова методов с необязательными и именованными аргументами.
**Требуется:** найти нарушения, назвать коды (`CS1737`, `CS1736`, `CS8323`, `CS1739`, `CS1744`), разнести по группам «объявление» и «вызов».

## Теоретическая справка
**Именованные аргументы** позволяют указать значение параметра по имени: `Show(name: "A", num: 1, prod: "Z")`. Порядок тогда не важен.

Правила:

- позиционные аргументы идут **перед** именованными, кроме случая, когда именованные стоят на своих местах (`CS8323` иначе);
- имя должно существовать (`CS1739`);
- один параметр нельзя задать дважды — позицией и именем (`CS1744`).

Для **объявления** действуют правила необязательных параметров (порядок — `CS1737`, константность значения — `CS1736`).

## Идея решения
Разделяем ошибки объявления (порядок и вид необязательных параметров) и ошибки вызова (именованные и позиционные аргументы).

## Решение
```csharp
// Исправленный фрагмент
static void Bad1(int b, int a = 1) { }                 // необязательный - после обязательного
static void Bad2(int n = 2026) { }                     // значение по умолчанию - константа
static void Show(string name, int num, string prod) { }
Show("Y", 31, prod: "X");                              // позиционные - перед именованными
Show("A", 1, prod: "Z");                               // существующее имя параметра
Show(name: "B", num: 1, prod: "A");                    // без дублирования
```

## Пошаговое объяснение
1. Объявление: `Bad1(int a = 1, int b)` — обязательный параметр после необязательного (`CS1737`); `Bad2(int n = DateTime.Now.Year)` — значение по умолчанию не константа (`CS1736`).
2. Вызов: `Show(prod: "X", 31, "Y")` — позиционные аргументы после именованного (`CS8323`).
3. `Show("A", 1, wrongName: "Z")` — у метода нет параметра `wrongName` (`CS1739`).
4. `Show("A", num: 1, name: "B")` — параметр `name` задан дважды: позицией и именем (`CS1744`).

## Трассировка и проверка
| Группа | Фрагмент | Код |
|---|---|---|
| объявление | `Bad1(int a = 1, int b)` | CS1737 |
| объявление | `Bad2(int n = DateTime.Now.Year)` | CS1736 |
| вызов | `Show(prod: "X", 31, "Y")` | CS8323 |
| вызов | `Show("A", 1, wrongName: "Z")` | CS1739 |
| вызов | `Show("A", num: 1, name: "B")` | CS1744 |

Исправленные вызовы: `Show("Y", 31, prod: "X")`, `Show("A", 1, prod: "Z")`, `Show(name: "B", num: 1, prod: "A")`.

## Результат
Объявление: CS1737, CS1736; вызов: CS8323, CS1739, CS1744.

## Типичные ошибки
- Ставить именованный аргумент раньше позиционных.
- Опечатываться в имени параметра при вызове.
- Задавать одному параметру значение дважды.
- Использовать `DateTime.Now` как значение по умолчанию (оно не константа).

## Задания для закрепления
- Заменить «неконстантное» значение по умолчанию типом `int?` и `null`.
- Показать, как именованные аргументы упрощают вызов метода с пятью необязательными параметрами.
- Составить ещё три нарушения с необязательными параметрами.
