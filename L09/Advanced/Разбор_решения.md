# Разбор решения. L09-ALG-021. Три нарушения в одном фрагменте

## Условие
Дан код:

```
int x = 5;
if (x > 0)
{
    break;
}

for (int i = 1; i <= 3; i++)
{
    goto Finish;
}

for (int i = 1; i <= 5; i++)
{
    break;
    Console.WriteLine(i);
}
```

Найти все нарушения, для каждого назвать код сообщения компилятора и объяснить причину отдельно. Указать, какие два из них являются ошибками, а какое — предупреждением, и почему различие существенно. Привести исправленный фрагмент.

## Ожидаемый результат
Три сообщения: ошибки `CS0139` и `CS0159`, предупреждение `CS0162`; отмечено, что предупреждение не препятствует сборке, из-за чего соответствующая ошибка проявляется только в поведении программы.

## Идея решения
Выясняем, где `break` и `goto` недопустимы, и какие сообщения останавливают сборку, а какие — нет.

## Решение
```csharp
// Исправленный фрагмент
int x = 5;
if (x > 0)
{
    Console.WriteLine("положительное");   // break вне цикла недопустим
}

for (int i = 1; i <= 3; i++)
{
    goto Finish;
}
Finish:
Console.WriteLine("конец");

for (int i = 1; i <= 5; i++)
{
    Console.WriteLine(i);
    break;
}
```

## Пошаговое объяснение
1. `break` внутри `if`, не находящегося в цикле или `switch`, — ошибка `CS0139`: прерывать нечего.
2. `goto Finish;` без объявленной метки `Finish` — ошибка `CS0159`: метка не найдена (после её добавления переход выходит из цикла).
3. `Console.WriteLine(i);` после `break` — недостижимый код; это лишь предупреждение `CS0162`, сборка не прерывается.
4. Различие существенно: ошибки не дают получить программу, а предупреждение допускает её запуск, поэтому недостижимая строка тихо не выполняется и проявляется только в поведении программы.

## Результат
Две ошибки (CS0139, CS0159) и предупреждение CS0162; исправлено расположением break, добавлением метки и перестановкой вывода перед break.
