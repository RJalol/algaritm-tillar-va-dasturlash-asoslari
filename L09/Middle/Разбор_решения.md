# Разбор решения. L09-ALG-006. Проверка простоты с досрочным выходом

## Условие
Переписать программу проверки простоты числа из темы №8 (задание ALG-014), добавив оператор `break` для выхода сразу после нахождения первого делителя. Добавить счётчик итераций и вывести его. Сравнить в комментарии число итераций с решением без `break` для числа 1000.

## Ожидаемый результат
Ответ о простоте совпадает с прежним решением, но число итераций для составного числа значительно меньше; в комментарии приведено сравнение.

## Разбор условия
**Дано:** программа проверки простоты числа (по теме №8).
**Требуется:** добавить `break`, счётчик итераций, сравнить число итераций с вариантом без `break` для числа 1000.

## Теоретическая справка
Для проверки простоты достаточно найти **один** делитель: число составное. После находки перебор продолжать бессмысленно.

Затраты на проверку: для составного числа — зависят от наименьшего делителя; для простого — всегда до √n. Эта разница и измеряется счётчиком итераций.

Счётчик итераций — простой способ **эмпирической оценки** эффективности: сравнивая его значения, видим выигрыш без измерения времени.

## Идея решения
Проверка простоты перебором делителей до √n. Как только найден первый делитель, число составное, и продолжать перебор бессмысленно — выходим `break`. Счётчик итераций показывает выигрыш.

## Решение
```csharp
using System;

class Program
{
    static void Main()
    {
        Console.Write("Введите число: ");
        int n = int.Parse(Console.ReadLine());

        bool isPrime = n >= 2;
        int iterations = 0;

        for (int d = 2; d * d <= n; d++)
        {
            iterations++;
            if (n % d == 0)
            {
                isPrime = false;
                break;                 // первый делитель найден
            }
        }

        Console.WriteLine(isPrime ? "Простое" : "Составное");
        Console.WriteLine("Итераций: " + iterations);

        // Для n = 1000 с break: делитель 2 найден на 1-й итерации (итераций 1).
        // Без break цикл прошёл бы все d от 2 до 31 (30 итераций).
    }
}
```

## Пошаговое объяснение
1. `isPrime` сначала равно `n >= 2` (числа меньше 2 не простые).
2. Цикл идёт по `d` пока `d*d <= n`; счётчик `iterations` растёт на каждой итерации.
3. При первом делителе меняем признак и прерываем цикл `break`.
4. Для 1000: делится на 2 сразу — 1 итерация; без `break` — 30 итераций (d = 2…31). Для простого числа выигрыша нет: перебираются все d.

## Трассировка и проверка
Для n = 1000 (√1000 ≈ 31,6; цикл идёт для `d` от 2 до 31):

| Вариант | Итераций | Комментарий |
|---|---:|---|
| с `break` | 1 | уже `d = 2` делит 1000 |
| без `break` | 30 | цикл проходит `d = 2…31` целиком |

Для простого 997: оба варианта выполняют 30 итераций — `break` не помогает, делителей нет. Это показывает, что выигрыш зависит от данных.

## Результат
Ответ о простоте тот же, что и без break; для составного 1000 итераций 1 вместо 30.

## Типичные ошибки
- Не сбросить признак простоты перед каждой проверкой.
- Не завершать цикл после находки делителя — ответ верен, но работа лишняя.
- Считать итерации после цикла, а не внутри него.
- Проверять делители до n−1, не используя границу √n.
