# Разбор решения. L21 · Задание II · №1. Два одноимённых класса

## Условие
Объявить два пространства имён — `Banking` и `Geometry` — и поместить в каждое класс с именем `Account` и `Point` соответственно так, чтобы в обоих пространствах имён оказался класс с общим именем `Record`, но с разным набором полей. Создать по объекту каждого типа и вывести их описания, обращаясь по полным именам. Подтвердить выводом, что типы различны.

## Ожидаемый результат
Оба объекта созданы и выведены; сравнение типов даёт `True` для их различия, а полные имена различаются пространствами имён.

## Разбор условия
**Дано:** два пространства имён `Banking` и `Geometry`, каждое с классом `Record`, но с разными полями.
**Требуется:** создать по объекту, вывести описания по полным именам и подтвердить различие типов.

## Теоретическая справка
Два типа с одним простым именем в разных пространствах — **разные типы**. Среда выполнения различает их по полному имени (и сборке).

Если в одном файле подключены оба пространства директивами `using`, простое имя `Record` становится **неоднозначным** (`CS0104`). Решения: указывать полное имя, использовать **псевдоним** `using B = Banking.Record;` либо не подключать одно из пространств.

## Идея решения
Одноимённые типы в разных пространствах имён не конфликтуют: их различают по полным именам. Для сравнения типов используем `GetType()`.

## Решение
```csharp
using System;

namespace Banking
{
    class Record
    {
        public string Owner = "Азиз";
        public decimal Balance = 1500;
        public override string ToString() => "Banking.Record: " + Owner + ", " + Balance;
    }
}

namespace Geometry
{
    class Record
    {
        public double X = 3;
        public double Y = 4;
        public override string ToString() => "Geometry.Record: (" + X + "; " + Y + ")";
    }
}

class Program
{
    static void Main()
    {
        Banking.Record a = new Banking.Record();
        Geometry.Record g = new Geometry.Record();

        Console.WriteLine(a);
        Console.WriteLine(g);
        Console.WriteLine(a.GetType() != g.GetType());
        Console.WriteLine(a.GetType().FullName);
        Console.WriteLine(g.GetType().FullName);
    }
}
```

## Пошаговое объяснение
1. В обоих пространствах объявлен класс с одним и тем же простым именем `Record`, но разным набором полей.
2. Обращаясь по полным именам (`Banking.Record`, `Geometry.Record`), мы однозначно указываем нужный тип.
3. Сравнение `GetType()` объектов даёт «не равны» — это разные типы.
4. Полные имена отличаются префиксом пространства имён.

## Трассировка и проверка
| Выражение | Результат |
|---|---|
| `a.GetType().FullName` | Banking.Record |
| `g.GetType().FullName` | Geometry.Record |
| `a.GetType() != g.GetType()` | True |

Поля у типов разные (`Owner`, `Balance` и `X`, `Y`), поэтому и описания отличаются; присвоить один объект переменной другого типа нельзя (`CS0029`).

## Результат
Выведены оба описания; сравнение типов (!=) даёт True; полные имена — Banking.Record и Geometry.Record.

## Типичные ошибки
- Подключить оба пространства `using` и обратиться к `Record` без уточнения (`CS0104`).
- Полагать, что два класса с одинаковыми именами и полями — один тип.
- Не различать полное и простое имя при выводе `GetType().Name`.
- Помещать различные по смыслу типы в одно пространство из-за нежелания набирать префикс.

## Задания для закрепления
- Применить псевдоним `using` для устранения неоднозначности.
- Разместить типы в разных файлах и убедиться, что результат тот же.
- Вывести `GetType().Namespace` для обоих объектов.
