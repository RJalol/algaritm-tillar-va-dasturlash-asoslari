# Разбор решения. L21 · Задание III · №1. Учебный проект из трёх слоёв

## Условие
Спроектировать проект `Academy` из трёх пространств имён — `Academy. Models`, `Academy. Services`, `Academy. Reports` — не менее чем с шестью классами, размещёнными по одному в файле, в папках, соответствующих пространствам имён. Слой `Reports` обращается к `Services`, слой `Services` — к `Models`; обратных обращений быть не должно. Программа выводит сводный отчёт по группе студентов.

## Ожидаемый результат
Отчёт выведен; в каждом файле объявлено пространство имён уровня файла, а набор директив `using` каждого файла отражает заявленное направление зависимостей.

## Разбор условия
**Дано:** учебный проект `Academy`.
**Требуется:** три пространства имён (`Models`, `Services`, `Reports`), не менее шести классов по одному в файле, папки по пространствам, зависимости только «вниз»; вывести сводный отчёт по группе.

## Теоретическая справка
**Слоистая архитектура.** Зависимости направлены в одну сторону: `Reports → Services → Models`. Нижний слой ничего не знает о верхних; благодаря этому модели можно использовать повторно, а изменения отчётов не затрагивают сервисы.

Принципы организации:

- **один класс — один файл**, имя файла совпадает с именем класса;
- **папка = пространство имён**: файл `Models/Student.cs` объявляет `namespace Academy.Models;`;
- **пространство имён уровня файла** (`namespace X;`, C# 10) экономит уровень вложенности;
- набор `using` в файле отражает его зависимости — по ним легко проверить, нет ли обратных связей.

## Идея решения
Слоистая архитектура: `Models` ничего не знает о других слоях, `Services` использует `Models`, `Reports` использует `Services`. Каждый класс — в своём файле, структура папок повторяет пространства имён.

## Решение
```csharp
// Структура проекта:
// Academy/
//   Program.cs
//   Models/Student.cs
//   Models/Group.cs
//   Services/GradeCalculator.cs
//   Services/GroupService.cs
//   Reports/ReportBuilder.cs
//   Reports/ReportPrinter.cs

// ---- Models/Student.cs ----
namespace Academy.Models;
public class Student
{
    public string Name { get; }
    public int Score { get; }
    public Student(string name, int score) { Name = name; Score = score; }
}

// ---- Models/Group.cs ----
using System.Collections.Generic;
namespace Academy.Models;
public class Group
{
    public string Title { get; }
    public List<Student> Students { get; } = new List<Student>();
    public Group(string title) { Title = title; }
}

// ---- Services/GradeCalculator.cs ----
using Academy.Models;
namespace Academy.Services;
public class GradeCalculator
{
    public double Average(Group g)
    {
        double sum = 0;
        foreach (Student s in g.Students) sum += s.Score;
        return g.Students.Count == 0 ? 0 : sum / g.Students.Count;
    }
}

// ---- Services/GroupService.cs ----
using Academy.Models;
namespace Academy.Services;
public class GroupService
{
    public Student Best(Group g)
    {
        Student best = g.Students[0];
        foreach (Student s in g.Students)
            if (s.Score > best.Score) best = s;
        return best;
    }
}

// ---- Reports/ReportBuilder.cs ----
using Academy.Models;
using Academy.Services;
namespace Academy.Reports;
public class ReportBuilder
{
    private readonly GradeCalculator _calc = new GradeCalculator();
    private readonly GroupService _service = new GroupService();

    public string Build(Group g) =>
        $"Группа {g.Title}: студентов {g.Students.Count}, " +
        $"средний балл {_calc.Average(g):F2}, лучший - {_service.Best(g).Name}";
}

// ---- Reports/ReportPrinter.cs ----
namespace Academy.Reports;
public class ReportPrinter
{
    public void Print(string text) => System.Console.WriteLine(text);
}

// ---- Program.cs ----
using Academy.Models;
using Academy.Reports;

Group group = new Group("ТТ-11");
group.Students.Add(new Student("Азиз", 87));
group.Students.Add(new Student("Дилноза", 92));
group.Students.Add(new Student("Рустам", 78));

new ReportPrinter().Print(new ReportBuilder().Build(group));
```

## Пошаговое объяснение
1. Выделяем три слоя и шесть+ классов: `Student`, `Group` (Models); `GradeCalculator`, `GroupService` (Services); `ReportBuilder`, `ReportPrinter` (Reports).
2. В каждом файле используем пространство имён уровня файла (`namespace Academy.Models;`), совпадающее с папкой.
3. Направление зависимостей читается по `using`: в файлах `Models` нет `using` на другие слои; `Services` подключает только `Academy.Models`; `Reports` — `Academy.Models` и `Academy.Services`.
4. Обратных зависимостей нет: `Models` не ссылается на `Services`, `Services` — на `Reports`.
5. `Program.cs` собирает данные и печатает отчёт.

## Трассировка и проверка
Контроль зависимостей по директивам `using`:

| Файл | using | Допустимо? |
|---|---|:--:|
| Models/Student.cs | — | да |
| Services/GradeCalculator.cs | Academy.Models | да |
| Reports/ReportBuilder.cs | Academy.Models, Academy.Services | да |
| Models/… | Academy.Services | **нет** (обратная зависимость) |

Результат работы программы для трёх студентов: «Группа ТТ-11: студентов 3, средний балл 85,67, лучший — Дилноза».

## Результат

## Типичные ошибки
- Помещать несколько классов в один файл и терять связь «файл — класс».
- Создавать циклические зависимости между пространствами имён.
- Класть в `Models` логику отчётов.
- Забывать делать классы `public`, когда к ним обращаются из другого пространства (по умолчанию `internal` — это допустимо в одном проекте, но не между проектами).
