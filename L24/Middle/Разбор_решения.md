# Разбор решения. L24 · Задание II · №1. Побочное действие в аргументе

## Условие
В классе задания I.3 передавать частичному методу аргументом выражение, вычисление которого выводит сообщение и увеличивает счётчик. Запустить программу дважды: с реализацией частичного метода и без неё. Сравнить оба вывода и значение счётчика.

## Ожидаемый результат
Без реализации сообщение вычисления аргумента не выводится и счётчик не увеличивается вовсе; с реализацией — выводится при каждом обращении.

## Разбор условия
**Дано:** класс с частичным методом.
**Требуется:** передавать частичному методу аргумент с побочным действием; запустить программу с реализацией метода и без неё; сравнить вывод и счётчик.

## Теоретическая справка
**Частичный метод** (`partial void M(...)`) объявляется в одной части, а реализуется — по желанию — в другой. Если реализации нет, компилятор **удаляет все вызовы** метода вместе с вычислением аргументов.

Условия «старого» частичного метода: возвращает `void`, нет `out`-параметров и модификаторов доступа. В современных версиях допустимы расширенные частичные методы с модификаторами и возвращаемыми значениями — но тогда реализация обязательна.

Следствие: **побочные эффекты в аргументах** частичного метода исчезают вместе с вызовом.

## Идея решения
Если у частичного метода (без модификаторов доступа, возвращающего `void`) нет реализации, компилятор удаляет *все его вызовы вместе с вычислением аргументов*. Поэтому побочные действия в аргументах пропадают.

## Решение
```csharp
using System;

partial class Logger
{
    public static int Counter;

    // Объявление частичного метода
    static partial void Log(string message);

    static string Make(string text)
    {
        Console.WriteLine("Вычисляется аргумент: " + text);
        Counter++;
        return text;
    }

    public static void Run()
    {
        Log(Make("первое"));
        Log(Make("второе"));
        Console.WriteLine("Счётчик = " + Counter);
    }
}

// Закомментируйте эту часть, чтобы запустить программу БЕЗ реализации:
partial class Logger
{
    static partial void Log(string message)
    {
        Console.WriteLine("LOG: " + message);
    }
}

class Program
{
    static void Main() { Logger.Run(); }
}
```

## Пошаговое объяснение
1. `Log` объявлен как частичный метод; `Make` печатает сообщение и увеличивает счётчик.
2. Запуск **с** реализацией: при каждом вызове сначала вычисляется аргумент (сообщение «Вычисляется аргумент…», `Counter++`), затем выполняется `Log`. Счётчик в конце равен 2.
3. Запуск **без** реализации (вторая часть удалена): компилятор исключает вызовы `Log(...)` целиком, в том числе вызовы `Make`. Сообщений нет, счётчик равен 0.
4. Вывод: не помещайте в аргументы частичных методов выражения с побочными эффектами, от которых зависит логика программы.

## Трассировка и проверка
| Вариант | Вывод аргументов | Счётчик в конце |
|---|---|--:|
| есть реализация | «Вычисляется аргумент…» ×2, LOG ×2 | 2 |
| реализации нет | ничего | 0 |

Во втором случае вызов `Log(Make("первое"))` вырезан целиком, поэтому `Make` не выполнялся.

## Результат
С реализацией: два сообщения аргументов, два LOG, Счётчик = 2. Без реализации: только «Счётчик = 0».

## Типичные ошибки

- Забыть, что без реализации вызовы исчезают.
- Объявить частичный метод с возвращаемым значением (`CS0759`/`CS8795` в старом синтаксисе).
- Реализовать метод с иной сигнатурой.
