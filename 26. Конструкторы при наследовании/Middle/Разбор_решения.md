# Разбор решения. L26 · Задание II · №1. Порядок инициализации

## Условие
Построить иерархию из трёх классов, в каждом из которых есть поле с инициализатором и конструктор. И инициализатор, и тело конструктора должны выводить сообщение с номером. Создать объект самого производного класса, применив при этом инициализатор объекта, и записать фактический порядок семи сообщений. Предсказать порядок до запуска и сравнить с полученным.

## Ожидаемый результат
Инициализаторы полей выполнились от самого производного класса к базовому, тела конструкторов — в обратном порядке, инициализатор объекта — последним; предсказание сверено с фактическим выводом.

## Разбор условия
**Дано:** иерархия из трёх классов, у каждого — поле с инициализатором и конструктор; создание объекта самого производного класса с инициализатором объекта.
**Требуется:** предсказать и проверить порядок семи сообщений.

## Теоретическая справка
Порядок создания объекта (C#):

1. **Инициализаторы полей** — от самого производного класса к базовому;
2. **Вызов конструктора базового класса** (рекурсивно вверх);
3. **Тела конструкторов** — от базового к производному;
4. **Инициализатор объекта** `{ Value = … }` — после конструктора.

Инициализаторы полей производного класса выполняются *до* вызова базового конструктора, чтобы поля были готовы, даже если базовый конструктор вызовет виртуальный метод производного класса.

## Идея решения
Порядок создания: (1) инициализаторы полей от самого производного класса к базовому, (2) тела конструкторов от базового к производному, (3) инициализатор объекта. Выведем сообщения и сверим с предсказанием.

## Решение
```csharp
using System;

class A
{
    int a = Log("3: инициализатор поля A");
    public A() { Console.WriteLine("4: тело конструктора A"); }
    public static int Log(string s) { Console.WriteLine(s); return 0; }
}

class B : A
{
    int b = Log("2: инициализатор поля B");
    public B() { Console.WriteLine("5: тело конструктора B"); }
}

class C : B
{
    int c = Log("1: инициализатор поля C");
    public int Value;
    public C() { Console.WriteLine("6: тело конструктора C"); }
}

class Program
{
    static void Main()
    {
        C obj = new C { Value = Log("7: инициализатор объекта") };
    }
}
```

## Пошаговое объяснение
1. Сообщения пронумерованы в порядке, который предсказывает теория. Сначала выполняются инициализаторы полей — от самого производного класса к базовому: C (1), B (2), A (3).
2. Затем выполняются тела конструкторов — от базового класса к производному: A (4), B (5), C (6).
3. Инициализатор объекта `{ Value = ... }` выполняется последним, уже после конструктора (7).
4. Запуск программы выводит сообщения именно в порядке 1…7 — предсказание совпадает с фактическим выводом.
5. Запомнить можно так: поля «сверху вниз», конструкторы «снизу вверх».

## Трассировка и проверка
Для `new C { Value = … }`:

| № | Сообщение |
|--:|---|
| 1 | инициализатор поля C |
| 2 | инициализатор поля B |
| 3 | инициализатор поля A |
| 4 | тело конструктора A |
| 5 | тело конструктора B |
| 6 | тело конструктора C |
| 7 | инициализатор объекта |

Запомнить: «поля — сверху вниз, конструкторы — снизу вверх».

## Результат
Сначала инициализаторы полей C → B → A, затем тела конструкторов A → B → C, затем инициализатор объекта — всего семь сообщений.

## Типичные ошибки
- Считать, что порядок инициализаторов полей совпадает с порядком конструкторов.
- Вызывать виртуальные методы из базового конструктора (производный объект ещё не завершён).
- Полагаться на то, что поле производного класса уже имеет значение в конструкторе базового.
- Путать инициализатор поля и присваивание в конструкторе.
