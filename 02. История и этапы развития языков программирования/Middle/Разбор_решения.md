## Ожидаемый результат

## Разбор условия
**Дано:** шесть языков — Fortran (ранний), Lisp, Prolog, Smalltalk, C#, SQL.
**Требуется:** определить основную парадигму каждого и обосновать выбор.
**Допущение:** «ранний» Fortran — язык 1950–1960-х годов, до объектных расширений.

## Теоретическая справка
**Парадигма программирования** — совокупность идей и приёмов, определяющих стиль построения программ.

| Парадигма | Основная идея | Единица программы |
|---|---|---|
| Императивная (процедурная) | последовательность команд изменяет состояние | процедура |
| Функциональная | вычисление — применение функций без побочных эффектов | функция |
| Логическая | программа — факты и правила, ответ ищет интерпретатор | предикат |
| Объектно-ориентированная | программа — взаимодействующие объекты | класс, объект |
| Декларативная | описывается результат, а не способ его получения | запрос, описание |

**Мультипарадигменность** — поддержка нескольких парадигм в одном языке; характерна для современных языков (C#, Python, Scala).

## Идея решения
Парадигма определяется основным способом описания вычислений: последовательность команд, функции, логические правила, объекты и сообщения, описание результата без указания шагов.

## Решение
```text
Язык              Парадигма                          Обоснование
Fortran (ранний)  процедурная (императивная)         программа — последовательность операторов и подпрограмм
Lisp              функциональная                     программа — выражения и функции; код = данные (списки)
Prolog            логическая                         программа — факты и правила, вывод выполняет интерпретатор
Smalltalk         объектно-ориентированная           всё — объект; вычисление — отправка сообщений
C#                мультипарадигменная (ООП основа)   классы + функциональные средства (LINQ, лямбда) + императивный стиль
SQL               декларативная                      описывается, ЧТО получить, а не КАК
```

## Пошаговое объяснение
1. Сначала формулируем признак парадигмы: как описывается вычисление.
2. Fortran и подобные ранние языки описывают последовательность действий над переменными — императивная (процедурная) модель.
3. Lisp строится на вычислении выражений и применении функций — функциональная парадигма.
4. Prolog описывает знания фактами и правилами, а ответ ищет механизм логического вывода.
5. Smalltalk — «чистое» ООП: даже числа являются объектами.
6. SQL указывает желаемый результат запроса, план выполнения выбирает СУБД — декларативный подход.
7. C# сочетает несколько парадигм: основа — ООП, но есть лямбда-выражения, LINQ, паттерн-матчинг, поэтому язык называют мультипарадигменным.

## Трассировка и проверка
Проверочные вопросы для каждого языка:

- **Fortran:** есть ли в программе объекты или функции-значения? Нет — она состоит из операторов присваивания, циклов и подпрограмм → императивный стиль.
- **Lisp:** можно ли выразить программу только вложенными вызовами функций? Да → функциональный.
- **Prolog:** задаёт ли программист порядок шагов? Нет, он задаёт факты `родитель(анна, иван).` и правила → логический.
- **Smalltalk:** есть ли в языке что-то, кроме объектов и сообщений? Нет, даже числа — объекты → чисто ООП.
- **SQL:** описывает ли запрос `SELECT … WHERE …` порядок обхода таблицы? Нет, только желаемый результат → декларативный.
- **C#:** допускает классы, лямбда-выражения, LINQ и обычные циклы одновременно → мультипарадигменный.

## Типичные ошибки
- Назвать SQL «процедурным» из-за того, что запросы записываются построчно: порядок записи не равен порядку выполнения.
- Считать язык принадлежащим одной парадигме только по названию («объектно-ориентированный C++» поддерживает и процедурный стиль).
- Не отличать декларативную парадигму от функциональной: функциональные программы всё же определяют вычисление функциями.
- Давать обоснование без признака («потому что так принято») вместо проверки по критерию.
