# L20. Статические члены класса. Статические методы и их ссылки. Статические классы

Практические задания к теме №20 дисциплины «Алгоритмические языки и программирование» (версия V3).

## Особенность этой темы

Все члены, встречавшиеся до сих пор, принадлежали **экземпляру**: у каждого объекта свой остаток, своё имя, свой балл. Но некоторые величины принадлежат **типу в целом** — число созданных объектов, название учебного заведения, значение π.

Тема №20 заодно объясняет то, что читатель принимал на веру начиная с первой программы курса: почему `Math.Sqrt` вызывается без создания объекта, почему `Main` обязан быть статическим и откуда бралась ошибка `CS0120`, встречавшаяся с темы №13.

Два зеркальных нарушения, вокруг которых построены задания ALG-005, ALG-014 и ALG-015:

| Запись | Код | Смысл |
|---|---|---|
| `Counter.Value` (поле экземпляра через имя класса) | `CS0120` | обращение к члену объекта **без объекта** |
| `c.Total` (статическое поле через объект) | `CS0176` | обращение к члену типа **через объект** |

Не используются: **события**, **обобщённые типы** (темы №34–35), **пространства имён** (тема №21), **частичные классы** и подробное рассмотрение `const`/`readonly` (тема №23), **наследование** (темы №24–26).

## Ключевые идеи темы, проверяемые заданиями

- Статический член принадлежит **типу**, существует в **одной** копии и доступен, когда ни одного объекта ещё нет (ALG-001, ALG-003).
- К статическому члену обращаются **по имени класса**; через объект — `CS0176` (ALG-005, ALG-015).
- Статический метод не видит членов экземпляра — `CS0120`; обратное направление разрешено (ALG-014).
- Статический конструктор объявляется **без модификатора доступа и без параметров** (`CS0515`, `CS0132`) и выполняется **один раз**, перед первым обращением к типу (ALG-011, ALG-018, ALG-019).
- Инициализаторы статических полей выполняются **до** статического конструктора (ALG-029).
- Статический класс содержит только статические члены (`CS0708`), не имеет конструкторов экземпляра (`CS0710`), не создаётся (`CS0712`) и не допускает переменных своего типа (`CS0723`) — одна строка `new Util()` даёт **два** кода сразу (ALG-016, ALG-017, ALG-021).
- `const` вычисляется при компиляции, `static readonly` — при выполнении (ALG-013, ALG-025).
- Изменяемое статическое поле — по существу **глобальная переменная** (ALG-027).

## О диагностических заданиях

Задания Middle ALG-014–ALG-019 и Advanced ALG-021, ALG-029, ALG-030 содержат код для анализа: найти ошибку, назвать её код либо предсказать порядок вывода до запуска.

Все коды сообщений (`CS0120`, `CS0132`, `CS0176`, `CS0515`, `CS0708`, `CS0710`, `CS0712`, `CS0723`) и **все числовые ответы** (счётчик `0` → `3`; номера `1001`–`1003`; `MathHelper.Square(7)` = `49` и `CircleArea(2)` = `12,5664`; счета `3000,00` / `1000,00`, после операций `3200,00` / `1066,67`; пересчёт `212`, `32`, `100,00`; строки журнала `001`–`003`) проверены фактической компиляцией и запуском на .NET 8 с культурой ru-RU.

Отдельно проверен запуском **момент выполнения** статического конструктора: он сработал после первой строки программы, перед первым обращением к классу, и **только один раз**, тогда как конструктор экземпляра выполнился дважды. Проверен и порядок инициализации: инициализатор статического поля выполняется **раньше** статического конструктора.
