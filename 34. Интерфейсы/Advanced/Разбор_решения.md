# Разбор решения. L34 · Задание III · №1. Библиотека учебного заведения

## Условие
Разработать библиотеку классов (тема №27), в которой присутствуют: абстрактный класс с иерархией из четырёх классов; не менее трёх интерфейсов, реализуемых типами из разных ветвей иерархии и одним типом вне её; один класс, реализующий два интерфейса сразу; одна структура, реализующая интерфейс. Приложение собирает объекты в массивы по интерфейсам и печатает отчёты.

## Ожидаемый результат
Каждый массив типа интерфейса содержит объекты не связанных наследованием типов; для каждого решения (наследование либо интерфейс) приведено обоснование.

## Разбор условия
**Дано:** учебное заведение.
**Требуется:** библиотека с абстрактной иерархией, не менее трёх интерфейсов (в том числе для типа вне иерархии), класс с двумя интерфейсами, структура с интерфейсом; приложение собирает массивы по интерфейсам; обоснование наследование/интерфейс.

## Теоретическая справка
**Как выбирать.**

| Вопрос | Ответ → средство |
|---|---|
| Отношение «является» и общее состояние? | наследование |
| Общая *способность* у несвязанных типов? | интерфейс |
| Нужна реализация «по умолчанию» и поля? | абстрактный класс |
| Нужен тип-значение с общим поведением? | структура + интерфейс |

**Упаковка:** помещение структуры в переменную интерфейсного типа создаёт копию в куче (boxing); поэтому структуры в интерфейсных массивах менее эффективны, но допустимы.

## Идея решения
Иерархию строим наследованием («является»), а общие способности, которые есть у разнородных типов, — интерфейсами («умеет»). Один класс реализует два интерфейса, структура реализует интерфейс. Компактный вариант решения:

## Решение
```csharp
using System;
using System.Collections.Generic;
using System.Linq;

namespace Academy                                                 // библиотека классов
{
    public interface IPaid       { decimal MonthlyPay { get; } }
    public interface IContactable { string Email { get; } }
    public interface IPrintableReport { string Report(); }

    public abstract class Person
    {
        public string Name { get; }
        protected Person(string name) { Name = name; }
        public abstract string Role { get; }
    }

    public class Student : Person, IContactable, IPrintableReport     // два интерфейса сразу
    {
        public string Email { get; }
        public int Score { get; }
        public Student(string name, string email, int score) : base(name) { Email = email; Score = score; }
        public override string Role => "Студент";
        public string Report() => $"{Role} {Name}, балл {Score}";
    }

    public class Teacher : Person, IPaid, IContactable, IPrintableReport
    {
        public decimal MonthlyPay { get; }
        public string Email { get; }
        public Teacher(string name, string email, decimal pay) : base(name) { Email = email; MonthlyPay = pay; }
        public override string Role => "Преподаватель";
        public string Report() => $"{Role} {Name}, оклад {MonthlyPay:N0}";
    }

    public class Dean : Teacher
    {
        public Dean(string name, string email, decimal pay) : base(name, email, pay * 1.5m) { }
        public override string Role => "Декан";
    }

    public class Staff : Person, IPaid
    {
        public decimal MonthlyPay { get; }
        public Staff(string name, decimal pay) : base(name) { MonthlyPay = pay; }
        public override string Role => "Сотрудник";
    }

    public class Sponsor : IPaid, IPrintableReport                    // вне иерархии Person
    {
        public string Company { get; }
        public decimal MonthlyPay { get; }
        public Sponsor(string company, decimal pay) { Company = company; MonthlyPay = pay; }
        public string Report() => $"Спонсор {Company}, взнос {MonthlyPay:N0}";
    }

    public readonly struct Scholarship : IPaid, IPrintableReport     // структура реализует интерфейс
    {
        public string Holder { get; }
        public decimal MonthlyPay { get; }
        public Scholarship(string holder, decimal pay) { Holder = holder; MonthlyPay = pay; }
        public string Report() => $"Стипендия {Holder}, {MonthlyPay:N0}";
    }
}

class Program                                                          // приложение
{
    static void Main()
    {
        var s1 = new Academy.Student("Азиз", "aziz@edu.uz", 87);
        var s2 = new Academy.Student("Дилноза", "dil@edu.uz", 92);
        var t = new Academy.Teacher("Нодира", "nodira@edu.uz", 6_000_000);
        var d = new Academy.Dean("Саид", "said@edu.uz", 6_000_000);
        var staff = new Academy.Staff("Камола", 3_000_000);
        var sponsor = new Academy.Sponsor("TechCorp", 10_000_000);
        var scholarship = new Academy.Scholarship("Азиз", 800_000);

        Academy.IPaid[] payers = { t, d, staff, sponsor, scholarship };
        Academy.IContactable[] contacts = { s1, s2, t, d };
        Academy.IPrintableReport[] reports = { s1, s2, t, d, sponsor, scholarship };

        Console.WriteLine("Платежи в месяц: " + payers.Sum(p => p.MonthlyPay).ToString("N0"));
        foreach (var c in contacts) Console.WriteLine("E-mail: " + c.Email);
        foreach (var r in reports) Console.WriteLine(r.Report());
    }
}
```

## Пошаговое объяснение
1. Наследование выбрано там, где есть отношение «является»: `Student`, `Teacher`, `Staff` — это `Person`; `Dean` — это `Teacher`.
2. Интерфейсы выбраны для способностей, которыми обладают разнородные типы: `IPaid` реализуют преподаватели и сотрудники (иерархия), спонсор (вне иерархии) и стипендия (структура).
3. `Student` реализует два интерфейса сразу (`IContactable` и `IPrintableReport`), `Teacher` — три.
4. `Scholarship` — структура: она не может наследовать класс, но интерфейс реализовать может; при помещении в массив интерфейса происходит упаковка.
5. Каждый из массивов интерфейсного типа содержит объекты, не связанные наследованием друг с другом, и приложение обрабатывает их единообразно.

## Трассировка и проверка
| Массив | Элементы |
|---|---|
| `IPaid[]` | преподаватель, декан, сотрудник, спонсор, стипендия |
| `IContactable[]` | студенты, преподаватель, декан |
| `IPrintableReport[]` | студенты, преподаватели, спонсор, стипендия |

Каждый массив объединяет типы разных ветвей иерархии, а `Sponsor` и `Scholarship` (структура) вообще не относятся к `Person`.

## Результат
Выведены суммарные платежи, e-mail’ы и отчёты по трём массивам интерфейсов; для каждого решения (наследование или интерфейс) дано обоснование.

## Типичные ошибки
- Выводить всё в иерархию наследования, даже когда нужна способность.
- Создавать «жирные» интерфейсы с десятком членов.
- Не учитывать упаковку структур.
- Забывать обоснование выбора.
