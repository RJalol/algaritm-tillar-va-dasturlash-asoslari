# Разбор решения. L19-ALG-006. Класс «термостат»

## Условие
Объявить класс `Thermostat` со скрытым полем целевой температуры, скрытыми константами допустимых пределов (от 5 до 35 градусов), открытым свойством только для чтения и открытым методом `Set`, возвращающим `false` при выходе за пределы. Конструктор обязан пользоваться тем же методом. Проверить: создание со значением 22; попытка задать 40; задание 18; создание со значением 100.

## Ожидаемый результат
Выведено `22,0 C`; попытка задать 40 даёт `False`, температура осталась `22,0 C`; задание 18 даёт `True`; создание со значением 100 даёт `0,0 C`, поскольку конструктор вызвал тот же метод и тот отверг значение.

## Разбор условия
**Дано:** термостат с пределами 5…35 градусов.
**Требуется:** класс `Thermostat` со скрытым полем температуры, скрытыми константами пределов, свойством только для чтения и методом `Set`, возвращающим `false` при выходе за пределы; конструктор использует тот же метод.

## Теоретическая справка
Принцип **единой точки изменения состояния**: все пути записи в поле проходят через один метод с проверкой. Тогда нарушить инвариант (условие, всегда верное для объекта) нельзя ни из конструктора, ни снаружи.

Константы (`const`) пределов — закрытые: пользователю класса знать их не нужно. Метод `Set` возвращает `bool` — информирует вызывающего об успехе без исключений.

Особенность конструктора: он не может «отказаться» создавать объект через возврат `false`. Поэтому при недопустимом значении поле остаётся значением по умолчанию (0), либо конструктор бросает исключение — вопрос проектирования.

## Идея решения
Допустимые пределы хранятся в закрытых константах, а единственная точка изменения температуры — метод `Set`, который конструктор тоже использует.

## Решение
```csharp
using System;

class Thermostat
{
    private const double Min = 5;
    private const double Max = 35;
    private double _target;

    public double Target { get { return _target; } }

    public Thermostat(double target)
    {
        Set(target);               // тот же метод проверяет и в конструкторе
    }

    public bool Set(double t)
    {
        if (t < Min || t > Max) return false;
        _target = t;
        return true;
    }
}

class Program
{
    static void Main()
    {
        Thermostat t = new Thermostat(22);
        Console.WriteLine(t.Target + " C");
        Console.WriteLine(t.Set(40));
        Console.WriteLine(t.Target + " C");
        Console.WriteLine(t.Set(18));
        Thermostat u = new Thermostat(100);
        Console.WriteLine(u.Target + " C");
    }
}
```

## Пошаговое объяснение
1. Константы и поле закрыты — внешний код не может обойти проверку.
2. `Set` возвращает `false`, не меняя состояние, если значение вне [5; 35].
3. Конструктор вызывает `Set`; при 100 значение отвергнуто, поле осталось нулевым (значение по умолчанию для `double`).
4. Порядок проверки: 22 → принято; 40 → `False`, остаётся 22; 18 → `True`; `new Thermostat(100)` → 0 C.

## Трассировка и проверка
| Действие | Результат метода | `Target` |
|---|:--:|--:|
| `new Thermostat(22)` | `Set(22)` → true | 22,0 |
| `t.Set(40)` | false | 22,0 |
| `t.Set(18)` | true | 18,0 |
| `new Thermostat(100)` | `Set(100)` → false | 0,0 |

Последняя строка показывает слабое место: объект создан с некорректным состоянием 0 — в промышленном коде здесь выбросили бы исключение.

## Результат
22 C / False / 22 C / True / 0 C

## Типичные ошибки
- Делать пределы открытыми и менять их из любого места.
- Дублировать проверку в конструкторе и в `Set` — рано или поздно они разойдутся.
- Игнорировать возвращаемое значение `Set`.
- Возвращать из конструктора код ошибки (конструктор ничего не возвращает).

## Задания для закрепления
- Изменить конструктор так, чтобы он бросал `ArgumentOutOfRangeException`.
- Добавить методы `Increase` и `Decrease`, не выходящие за пределы.
- Добавить событие «температура изменилась».
