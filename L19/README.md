# L19. Инкапсуляция в C#. Модификаторы доступа: public, private, protected, internal

Практические задания к теме №19 дисциплины «Алгоритмические языки и программирование» (версия V3).

## Особенность этой темы

Во всех темах, начиная с №16, члены классов объявлялись словом `public`. Это делало бесполезной значительную часть работы: свойство с проверкой из темы №17 защищает поле лишь до тех пор, пока **само поле недоступно извне**.

Задание ALG-005 показывает это в чистом виде: два класса с одинаковым методом `Deposit`, отвергающим отрицательные суммы, ведут себя по-разному —

| Вариант | `Deposit(-100)` | `Balance = -100` напрямую |
|---|---|---|
| поле `public` | проверка сработала | **прошло**: остаток отрицательный |
| поле `private` + свойство `{ get; }` | проверка сработала | **не компилируется** |

Тема №19 превращает защиту из соглашения в правило, соблюдение которого проверяет компилятор.

Не используются: уровни `protected internal` и `private protected` (только названы в таблице), модификатор `file`, **статические члены** (тема №20), **пространства имён** (тема №21), **частичные классы** (тема №23), **наследование** (темы №24–26) — запись `class Derived : Base` применяется только там, где это прямо указано, ради показа действия `protected`.

## Ключевые идеи темы, проверяемые заданиями

- Умолчание для членов класса и структуры — **`private`**, для типов верхнего уровня — **`internal`** (ALG-003, ALG-008, ALG-018, ALG-029).
- Обращение извне к скрытому члену — `CS0122`; присваивание при закрытом `set` — `CS0272`; отсутствие `set` вовсе — `CS0200`. Три разные ошибки, которые легко спутать (ALG-015, ALG-016).
- Модификатор отдельного метода доступа обязан быть **строго более ограничивающим**, чем доступ свойства — иначе `CS0273` (ALG-017, ALG-021, ALG-030).
- Открытый член не может опираться на менее доступный тип: для **метода** это `CS0050`, для **свойства** — `CS0053` (ALG-014, ALG-021, ALG-030).
- `private` означает «только содержащий тип» — поле недоступно **даже наследнику**; `protected` открывает его наследникам, `internal` — всей сборке (ALG-009, ALG-029).
- Скрыть поле мало: если класс отдаёт наружу **ссылку** на своё хранилище, внешний код изменит его в обход всех проверок, и компилятор промолчит (ALG-012, ALG-025).
- Скрытый конструктор не позволяет создать объект в недопустимом состоянии (ALG-011, ALG-026).
- Скрытое не входит в договор и потому может быть переписано без изменения кода-потребителя (ALG-020, ALG-027).

## О диагностических заданиях

Задания Middle ALG-014–ALG-018 и Advanced ALG-021, ALG-025, ALG-029, ALG-030 содержат код для анализа: найти ошибку, назвать её код либо предсказать доступность до компиляции.

Все коды сообщений (`CS0050`, `CS0053`, `CS0122`, `CS0200`, `CS0272`, `CS0273`) и **все числовые ответы** (термостат `22,0 C` и `0,0 C` при создании со значением 100; заказ `2 поз., 4000,00`; поля `Shared=2 Internal=3 Open=4`, видимые наследнику; переполнение стека на одиннадцатом значении, `Count=10`, снятие `10`, `TryPop` пустого стека даёт `False` и `0`) проверены фактической компиляцией и запуском на .NET 8 с культурой ru-RU.

## Формат каждого задания (V3)

Каждый файл `L19-ALG-XXX.md` содержит только два поля: **Условие** и **Ожидаемый результат**. **Готовые решения не приводятся.**
